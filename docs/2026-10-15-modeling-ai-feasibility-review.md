# LogBook 모델링 AI 확장 제안 및 가능성 검토 요청

- 작성일: 2026-10-15
- 대상 프로젝트: `C:\Coding\Logbook` — Hi-TESS LogBook
- 문서 목적: 모델링 관련 AI 활용 방향을 기록하고 Claude Code가 코드·데이터·운영 환경을 기준으로 실현 가능성을 검토하도록 한다.
- 상태: 탐색 제안. 구현 계획이나 성능 검증 결과가 아니다.
- 범위: BDF 구조 이해, 모델 검토, 부위 재사용, 수정·생성, 메시 개선, 설계 탐색.
- 제외: 보고서 RAG, 자연어 검색·질의응답, 문서 요약.
- 프로젝트 구분: LogBook은 WorkLog(ProjectLedger)와 별도 프로젝트다.

## 1. 핵심 제안

LogBook에 축적되는 BDF와 개정 이력을 활용해 **모델링 패턴을 학습하고 새 모델의 검토·재사용·수정을 돕는 AI**로 확장한다.

우선 추천 순서는 다음과 같다.

1. 모델링 이상 탐지 및 반복 구조 검토
2. 부위별 유사 모델 탐색
3. 번호 변경·재메시 대응 비교와 구조 부위 자동 인식
4. 과거 수정 사례를 이용한 수정 제안 및 제한된 부위 생성
5. 메시 개선, 설계 최적화, 해석 응답 예측

초기 기능의 결과는 대상 절점·요소·부위와 연결해 3D 뷰어에서 확인할 수 있어야 한다. 설명 문장만 생성하는 기능보다 실제 검토·선택·비교·모델 변경에 연결되는 기능을 목표로 한다.

### 확장 시 주의할 제약

- 현재 형상 서명은 절점·요소 ID를 포함한다. 번호 변경이나 재메시에도 유지되는 형상 유사도와는 구분해야 한다.
- 현재 `Model`은 표시 목적의 데이터 구조다. 하중·구속·카드 상세 의미를 모두 보존하는 해석용 표현으로 간주하면 안 된다.
- 현재 해석 검증의 통과는 임시 조건에서의 실행 완료 및 FATAL 부재를 의미한다. 실제 운용 하중에 대한 설계 적합성·응력 정확도·메시 수렴성을 보장하지 않는다.
- 단위계, 실제 하중·경계조건, 해석 결과를 모델 판과 연결하는 학습 데이터 계층은 별도 확인·설계가 필요하다.
- 보유 모델 수, 모델 계열별 분포, 오류 라벨, 사용 가능한 결과 파일, GPU와 라이선스 여건은 이번 탐색에서 확인하지 않았다.

## 4. 방향별 상세

### 4.1 모델링 이상 탐지

#### 사용 예

- 반복되는 보강재 중 하나만 다른 단면을 사용한 경우
- 비슷한 판 구역에서 두께가 갑자기 달라지는 경우
- 대칭 구조의 한쪽만 다른 보 방향·오프셋·연결을 가진 경우
- 거의 맞닿아 있지만 연결되지 않은 부위
- 유사한 연결부들과 다른 RBE 구성 또는 속성 배정

#### 구현 방향

명확하게 계산할 수 있는 오류는 규칙으로 검사한다. AI는 주변 구조와 과거 사례를 고려해 검토 후보를 정렬하고, 의도된 차이와 실수의 구분을 돕는다.

입력 후보는 요소별 길이·면적·방향·두께·재료·연결 관계다. 처음에는 통계적 이상 탐지를 기준선으로 만들고, 연결 맥락을 반영할 필요가 확인되면 그래프 신경망으로 확장한다.

출력에는 대상 EID/GRID/PID, 의심 이유, 비교 부위, 실제 값 차이, 3D 위치를 포함한다. 모델이 계산한 점수는 검증 없이 오류 확률로 표시하지 않는다.

#### 데이터와 한계

- 사용자 피드백: `실제 오류 / 의도된 차이 / 판단 보류`.
- 오래 보관된 모델도 오류를 포함할 수 있다. 보관 여부나 해석 실행 성공만으로 정상 라벨을 만들면 안 된다.
- 자유단·고립·비대칭 자체가 오류는 아니다. 구조적 의도에 따라 정상일 수 있다.
- 합성 오류를 학습에 쓸 수 있으나, 실제 오류에 대한 별도 평가가 필요하다.
- 그래프 이상 탐지 연구는 존재하지만 선박 BDF에서의 성능은 입증되지 않았다.

### 4.2 부위별 유사 모델 탐색

#### 사용 예

뷰어에서 브래킷이나 보강 구조를 선택하면 다른 호선·프로젝트의 비슷한 부위를 찾아 다음을 비교한다.

- 판 두께·보강재 단면
- 메시 배치·크기
- 주변 구조와의 연결 방식
- RBE 구성
- 이후 개정에서 변경된 내용

#### 구현 방향

1. 기하·연결·속성으로 부위를 나눈다.
2. 형상 특징으로 후보를 빠르게 찾는다.
3. 실제 치수·두께·재료·연결 구성으로 재사용 적합성을 비교한다.

회전·이동에 무관한 검색을 고려하되, 형상 유사도와 실제 크기는 분리해서 보존한다. 모양이 비슷하다는 이유만으로 구조적으로 동등하다고 판정하지 않는다. 좌우 반사와 방향성의 취급도 명시해야 한다.

#### 근거와 한계

HyperMesh shapeAI에 유사 부품 매칭 기능이 있다. 다만 LogBook의 대상은 쉘·보·강체가 섞인 해석 부위이므로 해당 상용 기능을 그대로 재현하거나 적용할 수 있다고 가정하지 않는다.

### 4.3 번호 변경·재메시 대응 비교

#### 목표

다음을 구분한다.

- 번호만 변경
- 메시 밀도만 변경
- 실제 형상 변경
- 같은 위치에서 두께·단면 변경
- 보강 구조 추가·삭제

#### 구현 방향

AI가 대응 후보를 찾고, 좌표·표면 거리·속성 등의 결정적 계산으로 차이를 확인한다. 재메시 전후에는 절점 일대일 대응이 없을 수 있으므로 면·부위 대응을 지원해야 한다.

점군 정합 연구를 참고할 수 있지만, 반복 구조에서는 서로 다른 프레임을 오인할 수 있다. 위치 기준, 구조 연결, 기준 부위 지정과 불확실한 대응의 보류가 필요하다.

### 4.4 구조 부위 자동 인식

#### 목표

요소 종류·PID를 넘어 `판 패널 / 보강재 / 브래킷 / 거더 / 개구부 주변 / 연결부`와 같은 구조 단위로 분할·분류한다.

#### 활용

- 같은 종류의 부위 일괄 선택
- 반복 구조 비교
- 부위별 점검 기준 적용
- 부분 모델 추출 시 필요한 주변 연결 포함
- 부위별 수정·생성 기능의 대상 지정

#### 구현 방향과 한계

평면성·법선·연결·PID 기반 분할을 먼저 시도하고 사람이 일부 라벨을 지정한다. 이후 AI가 분류 후보를 제안한다.

MeshCNN은 삼각형 메시, BRepNet은 CAD B-rep를 대상으로 한다. 현재 혼합 BDF 모델에 직접 적용할 수 있는 완제품으로 취급하지 않는다. 요소·절점·속성·강체 관계를 어떻게 표현할지 검토해야 한다.

### 4.5 수정 사례 학습·전파

#### 목표

개정 이력에서 어디를 어떻게 고쳤는지를 학습해 유사한 상황에 제안한다.

- 다른 호선의 유사 부위에 과거 수정 사례 제시
- 반복 구조 일부에만 적용된 수정의 누락 후보 발견
- 연결·속성 수정 후보 생성
- 수정 대상과 영향받는 주변 요소 표시

#### 필요한 기록

개정 이유를 최소한 `오류 수정 / 설계 변경 / 메시 개선 / 해석 조건 변경`으로 구분하고 승인·거절 이유를 보존한다.

개정판은 항상 개선 정답이 아니다. 설계안 비교나 임시 실험을 오류 수정으로 학습하지 않도록 해야 한다. ID가 유지되지 않은 개정은 먼저 부위 대응이 필요하다.

이 기능은 LogBook에 맞춘 제안이며, 보유 개정 이력의 품질과 사례 수를 확인해야 가능성을 평가할 수 있다.

### 4.6 제한된 부위 모델 생성

#### 시작 대상으로 제안하는 범위

- 두 판 사이 표준 브래킷
- 선택 패널의 보강재 배치안
- 검증된 연결 템플릿의 새로운 부위 적용
- 기존 부위의 치수·단면을 변경한 대안

#### 권장 처리 흐름

AI의 템플릿·배치·치수 후보 선택 → 정해진 생성 코드의 BDF 작성 → 참조·연결·요소 품질 검사 → 기존 모델과 3D 비교 → 필요한 해석 검증 → 새 판 등록.

원본을 바로 변경하지 않고 변경 후보와 근거를 검토 가능하게 만든다. 현재 표시용 파서만으로 손실 없는 BDF 수정·출력을 보장할 수 있는지 확인해야 한다. pyNastran은 읽기·쓰기 및 결과 접근 계층의 후보로 검토할 수 있다.

전체 모델 자유 생성보다 제한된 템플릿의 유효한 조합을 탐색하는 방식부터 평가한다.

### 4.7 메시 개선 추천

#### 후보 기능

- 왜곡이 큰 구역의 국부 재메시
- 개구부·브래킷 끝단 주변 세분화
- 판 분할 방향 및 메시 전이 구간 추천
- 반복 구조에 일관된 메시 패턴 적용

#### 단계 구분

1. 기하학적 품질 개선: 요소 형상과 연결 기준으로 평가.
2. 해석 정확도 개선: 실제 결과와 메시 수렴 데이터로 평가.

형상만으로 응력 오차나 수렴성을 확정할 수 없다. 사각형 메시 생성 강화학습 연구가 있지만 대규모 혼합 쉘·보 모델로의 일반화는 별도 연구 과제다.

### 4.8 설계 대안 탐색 및 응답 예측

두 접근을 분리한다.

| 접근 | 동작 | 예시 |
|---|---|---|
| 다음 해석안 선택 | 실제 해석 결과를 보며 유망한 설계 변수를 선택 | 응력·변위 조건을 만족하면서 중량을 줄이는 두께·단면 탐색 |
| 해석 응답 예측 | 입력과 결과를 학습한 대리모델로 빠르게 추정 | 변경안의 변위·응력 분포 미리보기 |

첫 번째는 제한된 설계 변수와 실제 솔버를 연결한 베이지안 최적화를 검토한다. 두 번째는 MeshGraphNet 계열 또는 상용 PhysicsAI 접근을 검토한다.

필수 데이터 연결은 다음과 같다.

`BDF 판 + 단위계 + 실제 하중·경계조건 + 해석 설정 + 결과 파일 + 결과 품질`

초기에는 반복 해석하는 한 종류의 브래킷·보강 패널 등으로 제한한다. 서로 다른 구조·하중을 무작정 섞지 않는다. 예측의 적용 범위와 불확실성을 평가하고 최종 후보는 필요한 실제 해석으로 확인한다.

## 5. 공통 기술 기반 제안

아래는 구현 확정 사항이 아니라 검토 항목이다.

1. **AI용 모델 표현**: 표시용 LBM과 별도로 원본 ID·좌표계·단위·요소·속성·재료·연결 관계 및 필요한 해석 조건을 보존한다.
2. **부위 단위 데이터**: 큰 모델 전체 외에 패널·연결부·국부 영역 단위로 처리하고, 결과를 원본 요소 ID로 되돌릴 수 있게 한다.
3. **근거가 있는 출력**: 점수뿐 아니라 비교 부위, 수치 차이, 대상 ID, 적용 범위 및 판단 보류를 제공한다.
4. **검토 이력**: 제안 수락·거절, 실제 수정, 수정 이유를 학습 가능한 형태로 기록한다.
5. **계산 작업 분리 검토**: 학습·추론이 현재 API와 변환·해석 워커를 막지 않도록 실행 구조를 검토한다.
6. **데이터 버전**: 모델 판·추출기 버전·특징 버전·학습 모델 버전·검토 결과를 연결한다.
7. **접근 권한 유지**: 유사 부위 검색과 학습 데이터 이용 시 기존 자료 권한을 어떻게 적용할지 검토한다.

## 6. 첫 파일럿 제안: 반복 구조 검토

### 범위

한 모델 안에서 비슷한 보강재·브래킷·연결부를 묶고, 그중 다른 속성·연결을 가진 부분을 3D에 표시한다.

### 검증할 가설

1. 구조적으로 비슷한 부위를 올바르게 묶을 수 있다.
2. 사람이 놓치기 쉬운 속성·연결 차이를 찾을 수 있다.
3. 오탐 부담보다 검토 시간 절감 효과가 크다.

### 시작 데이터

대표 모델 약 20~30개를 대상으로 데이터 특성과 사용성을 확인하는 파일럿을 제안한다. 이 숫자는 충분한 학습량이나 성능을 보장하는 기준이 아니다. 모델 크기·계열·반복 부위 수와 라벨 확보 가능성에 따라 조정한다.

### 비교 기준

- 규칙·기하학 기반 기준선과 AI 방법을 비교한다.
- 상위 검토 후보 중 실제 오류 비율, 모델당 오탐 수, 검토 시간을 측정한다.
- 알려진 오류 사례에 대한 탐지율도 확인한다. 상위 후보 정확도만으로 미탐을 숨기지 않는다.
- 합성 오류와 실제 오류를 분리해 평가한다.
- 같은 모델의 개정판·유사 호선이 학습용과 평가용에 섞여 성능이 부풀려지지 않도록 모델 계열 단위로 분리한다.
- 새로운 구조 계열에서의 성능과 판단 보류 동작을 확인한다.

### 다음 단계로 진행할 조건

수치 목표는 현업 검토자와 파일럿 전에 정한다. AI가 기준선보다 개선되지 않거나 경고 처리 부담이 크다면 범위를 줄이거나 규칙 기반 기능으로 유지한다. 개선이 확인되면 다른 모델의 유사 부위 탐색과 수정 제안으로 확장한다.

## 7. Claude Code에게 요청하는 검토

### 검토 범위와 원칙

이 문서를 구현 지시로 해석하지 말고 먼저 가능성을 검토한다. 코드·데이터를 읽고 확인 가능한 사실, 추정, 추가 확인이 필요한 항목을 구분한다. 저장소의 파일 수를 실제 운영 모델 수로 간주하지 않는다. 운영 데이터나 공유 폴더에 접근할 수 없다면 데이터 준비 수준을 미확인으로 남긴다.

### 구체적인 질문

1. 현재 코드의 파서·모델·비교·뷰어·워커를 어디까지 재사용할 수 있는가? 관련 파일·함수 근거를 제시하라.
2. 표시용 데이터에서 빠진 정보 중 각 후보 기능에 필수적인 것은 무엇인가? 특히 RBE, 보 방향·오프셋, 구속·하중, 좌표계와 단위계를 점검하라.
3. 모델링 이상 탐지와 반복 구조 검토 중 AI가 실제로 개선할 부분은 무엇인가? 규칙·통계·기하 알고리즘만으로 해결할 부분도 구분하라.
4. 쉘·보·RBE 혼합 구조를 어떤 형태로 표현하는 것이 적절한가? 요소 그래프, 절점 그래프, 부위 그래프 등의 장단점을 비교하라.
5. 부위 분할과 유사도 계산을 처음부터 학습해야 하는가? 학습 없이 만들 수 있는 기준선은 무엇인가?
6. 대규모 모델의 메모리·처리 시간 병목은 무엇인가? 대표 모델 규모를 확인하지 못하면 가정별로 제시하라.
7. 현재 개정 이력은 학습 쌍으로 쓸 수 있는가? 수정 이유·ID 유지·설계안 분기·중복 데이터 문제가 있는가?
8. BDF 수정·생성에는 현재 코드 확장과 pyNastran 도입 중 어떤 접근이 적절한가? 미지원 카드 보존과 INCLUDE 출력 문제를 검토하라.
9. Windows 운영 환경, Python 의존성, GPU, Nastran 라이선스 측면에서 현실적인 실행 구조는 무엇인가?
10. 연구 코드의 입력 형식·학습 데이터·라이선스·유지보수 상태가 실제 적용에 맞는가? 논문 성능을 우리 데이터의 예상 성능으로 전용하지 말라.
11. 가장 작은 파일럿은 무엇인가? 입력·출력·검증 데이터·성공 기준·중단 기준을 명시하라.
12. 첫 추천이 반복 구조 검토여야 하는가, 아니면 유사 부위 탐색이나 다른 기능이 더 나은가? 현 코드와 데이터 근거로 반론도 제시하라.

### 원하는 검토 결과 형식

- 후보별 판정: `바로 실험 가능 / 선행 작업 후 가능 / 연구 필요 / 현재 보류`.
- 판단 근거: 코드 위치, 필요한 데이터, 기술적 불확실성.
- 재사용 가능한 부분과 새로 필요한 부분.
- 우선순위 상위 1~2개와 선택 이유.
- 파일럿의 구체적 범위와 검증 방법.
- 공수 추정이 가능하면 가정을 명시한 범위로 제시. 데이터 접근·라벨링·GPU·솔버 가용성에 따른 차이를 구분.
- 사용자에게 확인할 정보는 결론을 바꾸는 핵심 질문만 정리.

### 바로 전달할 프롬프트

> `docs/2026-10-15-modeling-ai-feasibility-review.md`를 읽고, 현재 LogBook 코드와 확인 가능한 데이터 구조를 기준으로 AI 모델링 확장 가능성을 검토해줘. 보고서 RAG와 자연어 처리 방향은 제외해줘. 아직 구현하지 말고 각 후보의 실현 가능성, 기존 코드 재사용 범위, 필요한 데이터, 규칙 기반 대비 AI의 가치, 운영 제약을 평가해줘. 특히 반복 구조 검토·모델링 이상 탐지와 부위별 유사 모델 탐색을 비교하고, 가장 작은 파일럿 1~2개를 제안해줘. 확인한 사실과 추정은 구분하고 코드 위치를 근거로 남겨줘. 문서 7절의 질문과 결과 형식을 참고해줘.

## 8. 조사 근거 자료

작성 시점에 확인한 연구·공식 문서다. 범용 기술의 가능성을 뒷받침하며 LogBook 데이터에서의 성능을 증명하는 자료는 아니다. 제품 문서·라이선스·설치 조건은 도입 검토 시 다시 확인한다.

1. [Graph Anomaly Detection with Graph Neural Networks: Current Status and Challenges](https://arxiv.org/abs/2209.14930) — 그래프 이상 탐지 연구 개요.
2. [HyperMesh Match Parts](https://help.altair.com/hwdesktop/hwx/topics/pre_processing/model_build_and_assembly/group_parts_t.htm) — shapeAI 기반 유사 부품 매칭의 상용 사례.
3. [GeoTransformer 공식 구현](https://github.com/qinzheng93/GeoTransformer) — 부분 점군 대응·정합 연구. 반복 선박 구조와 FE 의미 대응은 별도 검증 필요.
4. [MeshCNN](https://ranahanocka.github.io/MeshCNN/) — 삼각형 메시 기반 분류·분할. 혼합 BDF에 직접 적용되는 모델은 아님.
5. [BRepNet](https://www.research.autodesk.com/publications/brep-net/) — CAD B-rep의 위상 정보를 사용하는 학습 연구. FE 메시와 입력 표현이 다름.
6. [pyNastran 공식 문서](https://pynastran-git.readthedocs.io/en/latest/) — BDF 읽기·쓰기 및 OP2 결과 접근 후보.
7. [Reinforcement learning for automatic quadrilateral mesh generation: a soft actor-critic approach](https://arxiv.org/abs/2203.11203) — 강화학습 기반 사각형 메시 생성 연구.
8. [BoTorch: constrained multi-objective optimization](https://botorch.org/docs/v0.17.0/tutorials/constrained_multi_objective_bo) — 제약조건을 포함한 다목적 베이지안 최적화 예제.
9. [NVIDIA PhysicsNeMo MeshGraphNet](https://docs.nvidia.com/physicsnemo/latest/user-guide/model_architecture/meshgraphnet.html) — 메시 기반 학습 구현·설명.
10. [PhysicsAI 공식 설명](https://help.altair.com/simlab/help/en_us/topics/physicsai/physicsai.htm) — 과거 시뮬레이션을 활용한 새 설계 응답 예측의 상용 사례.

## 9. 이번 기록의 한계

- 실제 운영 모델과 결과 파일을 표본 분석하지 않았다.
- AI 학습·추론이나 성능 벤치마크를 수행하지 않았다.
- 모델링 기능을 구현하거나 운영 설정을 변경하지 않았다.
- 제안의 추천 순서와 파일럿 규모는 검토 출발점이며 확정된 개발 계획이 아니다.
