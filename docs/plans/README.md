# Logbook 구현 계획 로드맵

설계 문서: `docs/specs/2026-09-28-logbook-design.md`

설계가 서로 독립적인 하위 시스템 여러 개로 이루어져 있어 **계획서를 6개로 나눈다.**
각 계획서는 그 자체로 동작·검증 가능한 결과물을 낸다. 다음 계획서는 앞 계획서가 끝난 뒤,
그 결과(특히 00 사전 실험)를 반영해 상세화한다.

| # | 계획서 | 산출물 | 선행 |
|---|---|---|---|
| **00** | `2026-09-28-logbook-00-poc.md` — 사전 실험 | 실험 스크립트 + `poc/RESULTS.md` + 설계 유지/수정 판정 | — |
| 01 | 기반 — 저장소 뼈대, 설정, DB 모델·마이그레이션, 사번 로그인·승인, 감사 로그, 저장소 경로 계층(`entry.json`), 프론트 셸(상단 바·좌측 탐색·디자인 토큰) | 로그인하고 빈 셸이 뜨는 앱 | 00 |
| 02a | `2026-09-29-logbook-02a-ingest-backend.md` — 올리기 백엔드: 워커·작업 큐, Inbox 감시·배치, 분류·해시·중복, 호선 추정, 묶음 제안(초안 Entry), 확정·Vault 이동·entry.json, 휴지통·복원, 쪼개기·합치기, API | Inbox 로 올리고 API 로 확정까지 | 01 |
| 02b | 올리기 화면 — 크롬 업로드(DRM 검사, `00_Inbox\_web`), 정리 대기 화면(묶음 카드·끌어 옮기기·확정), 휴지통 화면, 활동 로그 라벨 | 화면에서 올리고 확정까지 | 02a |
