# 48 — 찾기 메뉴 재검토: 업무별 메뉴 정리 · 관계 지도 입구 · 조건으로 선례 찾기

2026-10-28. 상태: 결정만(검토 문답으로 정함), 구현 전.

## 왜
좌측 '찾기' 아래 메뉴가 9개(검색·즐겨찾기·문서·호선·분류·관계 지도·갖춤 현황·선례 찾기·최근 비교)로 늘었다.
화면이 계획마다 하나씩 더해져(25·26·27 이 같은 날) 서로 겹치거나 들어오는 길이 없는 곳이 생겼고,
주 업무의 첫 순간(새 해석, 아직 모델 없음)에 쓸 화면이 없다. 자료 양·사용 빈도는 보지 않고(프로토타입, 자료 쌓기 전)
**지금 화면 구성만으로** 판단했다.

## 판단 기준
- 업무: **(a) 새 해석 전에 옛 모델·보고서를 찾아 다시 쓰기**(주), (b) 등록·정리(보조), (c) 갖춤 살피기·보고(가끔).
- 메뉴에 남기는 조건 = (a) 업무의 한 단계를 맡고 다른 메뉴로 대신할 수 없다, 또는 (b)·(c) 의 자주 쓰는 입구다.
  걸리지 않는 화면은 지우지 않고 다른 화면 안의 단추·탭·링크로 옮긴다.
- 빼기·합치기 먼저, 새 기능은 (a) 흐름의 분명한 구멍에만.

## 조사한 사실(2026-10-28)
- 검색(/)과 문서(/reports)는 본문 검색 엔진이 다르다 — MySQL ngram(`search/mysql_backend.py`) / SQLite FTS5 + OCR(`report_index/search.py`).
  검색은 그림 속 글자를 못 찾고, 문서 화면이 그 차이를 안내한다(`ReportsPage.jsx:505`).
- 분류(/browse) 값 링크는 모두 `/?{속성}=값` — 탭 8개가 검색 필터 8개와 같다. 분류에만 있는 것은 값 전체·건수(0건 포함) 보기.
- 호선 상세는 같은 시리즈만 보이고 같은 선종·크기급 자료는 없다. 호선 목록은 번호 거르기·열기·PLM 선종 채우기뿐.
- 선례 찾기는 기준 BDF(`file_id` 또는 업로드)가 있어야 시작한다(`routers/similar.py`).
- 관계 지도는 메뉴 말고 들어오는 길이 없고, 주소로 대상을 지정하지 못한다.
- 최근 비교는 비교 바구니 [최근]·빈 비교 화면에도 있다. 다만 바구니 띠는 담긴 것이 있을 때만 보인다(`CompareBasket.jsx:101`).
- 갖춤 현황 '손볼 자료' 5탭은 등급 제한 없이 모두 본다. '최근 본 자료' 기록은 없다.

## 바꿀 것(이 순서로)
### 1. 메뉴 정리
- 좌측 메뉴를 업무별로(찾기 9 → 6):
  ```
  찾아 쓰기   검색(자료|문서 본문) · 즐겨찾기 · 호선 · 선례 찾기
  살펴보기    관계 지도 · 갖춤 현황
  등록·정리   정리 대기(+손볼 자료 탭) · 휴지통
  기록        활동 로그
  ```
- **검색 ↔ 문서**: 메뉴는 '검색' 하나, 검색 화면 위 [자료 | 문서 본문] 전환. 전환해도 검색어와 두 화면 공통 조건(호선·구역 등)은 유지,
  한쪽에만 있는 조건은 그 화면에서만. 두 엔진 통합은 하지 않는다.
- **분류**: 메뉴에서 빼고 검색 필터 칸마다 [값 전체 보기] → 분류 화면(그 속성 탭).
- **최근 비교**: 메뉴에서 빼고 비교 바구니 띠가 비어도 [최근 비교] 단추는 늘 보이게.
- **손볼 자료**: 갖춤 현황 아래 5탭을 정리 대기의 두 번째 탭으로. 갖춤 현황은 칸 표만. 등급 제한은 지금처럼 없음.
- 옛 주소 `/reports`·`/browse`·`/compares` 는 그대로 열린다(즐겨찾기·WorkBench 링크 보호). 메뉴 강조는 새 자리에 맞춘다.

### 2. 관계 지도 입구
- `/graph?focus=<entry|hull>:<id>` — 열면 그 점을 골라 이어진 것을 강조(지금 점 고르기와 같은 상태).
- 자료 상세·호선 상세에 [지도에서 보기].

### 3. 조건으로 선례 찾기
- 선례 찾기에 두 번째 시작 방법 **'조건으로'**: 호선 번호(필수) + 구역·대상(선택). 기존 BDF 기준(LogBook·내 PC)은 그대로.
- 결과는 **같은 시리즈 / 같은 크기급 / 같은 선종** 세 칸, 칸 안은 검증 통과·문서 있는 자료 먼저. 각 줄에 모델·보고서·검증.
- 크기급·선종은 `plm_ship.ship_facets`(관계 지도·갖춤 현황과 같은 규칙), 시리즈는 `series_lead or hull_no`(45).
  PLM 에 없는 호선이면 시리즈 칸만 보이고 그 사실을 안내.
- 호선 상세에 [이 호선으로 선례 찾기] — 호선 상세에 비슷한 호선 목록을 따로 두지 않는다(한 곳에서만).

## 하지 않기로
