# 67 — 담당자 프로필 카드

작성 2026-11-23 · 상태: **1단계 구현**(2단계부터는 계획) · 사용자 요청: "LogBook 에 담당자 별로 프로필 카드 기능을 추가하고 싶어. 담당자가 직접 편집할 수도 있고,
그 담당자가 올린 업로드 자료들로 인해 특성 등의 정보가 저장될 수도 있어. 프로필 카드에서는 담당자가 올린 자료 및 담당자 자료들을 모두 확인도 가능해.
그 사람의 연구 역사를 보여주는 기능도 하고 싶어."

## 정한 것(사용자 확인 2026-11-23, 추천안 그대로)

1. **카드는 담당자 명부(`people`, 46) 기준이다.** 퇴사자와 사번 없는 사람도 카드가 있어야 그 사람이 남긴 지식을 볼 수 있다.
   명부의 사번이 `users` 와 같으면 '작성한 자료'(`entries.uploaded_by`)도 같은 카드의 탭으로 보인다.
2. **순위, 점수, 사람 사이 건수 비교는 넣지 않는다.** 실적 평가 도구로 읽히면 담당자 지정을 꺼리게 되고 자료 창고의 목적이 흔들린다.
   카드에는 그 사람 한 명의 분포만 보인다.
3. **1단계(읽기 전용 카드)부터** 만들고, 본인 편집과 연구 역사는 그 뒤에 단계별로 더한다.

## 하지 않는 것

- LLM 이 쓰는 자동 소개문("이 사람은 ○○ 전문"): 틀리면 본인에게 불쾌하고, 문서 요약도 아직 실패 원인을 못 잡았다(22, 2026-11-20).
- 사이드 메뉴 추가(규칙: 메뉴 8개 + 관리 1개). 진입점은 화면 안 링크와 계정 메뉴로 한다.
- 특성 값을 표에 저장하기: 관계 지도(25)와 갖춤 현황(26)처럼 화면을 열 때 이미 있는 값으로 계산한다. 자료를 고치면 카드가 저절로 맞춰진다.

## 착수 전 확인

- **145 의 담당자 지정 비율**: 확정 자료 중 담당자가 있는 자료, 작성자만 있는 자료의 수. 관리자 API(`/api/search?limit=200` 의 `assignees` 칸)로
  읽기만 한다.
- **결과(2026-11-23, Windows 로그인 LV3 로 읽기만 함)**: 확정 자료 141건 **모두 담당자가 있다**(빈 자료 0건). 담당자는 3명뿐이다
  (김미희 89건 퇴사, 권혁민 51건, 김도현 1건). 공동 담당 자료는 0건. 작성자는 141건 모두 한 사람(A476854)이다.
- **1단계에 주는 영향**
  - 카드가 비어 보일 걱정은 없다. 다만 지금 쓸모가 가장 큰 카드는 **퇴사자 김미희 카드(89건)** 다. 4단계로 미뤄 둔 '인수인계 묶음'(남긴 결론과 주의점 모아 읽기)을
    1단계 카드 안의 한 구역으로 당겨 온다.
  - '함께 일한 사람'은 지금 데이터로는 늘 비므로, 값이 없으면 구역을 숨긴다(빈 칸을 그리지 않는다).
  - '작성한 자료' 탭은 지금은 한 사람만 의미가 있다. 탭은 만들되 담당한 자료와 같으면(모두 겹치면) 탭 대신 한 줄 안내로 줄인다.
  - 다른 사람이 직접 올리기 시작해야 카드의 가치가 커진다. 카드 자체가 올리기를 늘리지는 않는다는 점을 기대치로 적어 둔다.

## 1단계 — 읽기 전용 카드

### 주소와 진입점
- 화면 `/p/{명부 번호}`(호선 `/h/`, 자료 `/e/` 와 같은 꼴). 사번만 아는 곳(작성자, 호선 참여자)은 서버가 사번으로 명부 행을 찾아 넘긴다.
  명부에 없는 작성자는 `users` 정보만으로 '작성한 자료' 탭 하나인 카드를 보인다(명부 행을 저절로 만들지 않는다).
- 진입점: 자료 상세의 담당자 이름(`AssigneeList`, 지금은 검색 링크 → 카드로, 카드 안에 '검색에서 모두 보기'), 작성자 이름, 호선 화면 참여자,
  계정 메뉴 '내 프로필'(명부에 내 사번이 있을 때). 탭 제목은 `lib/pageTitle.js`.

### 서버
- 모듈 `app/profile.py` `person_profile(db, person, user)`, API `GET /api/people/{id}/profile`, `GET /api/people/by-employee/{사번}/profile`.
  `hull_info.hull_detail` 과 같은 꼴로 만든다(N+1 없이 한 번에 읽기, 구역은 분류 목록 대표 값).
- **권한**: 확정 자료 중 보는 사람이 볼 수 있는 것만 센다(`access.visible_entries_filter`). 분포 숫자에도 블록 자료가 섞이지 않아야
  그런 자료가 있다는 사실이 드러나지 않는다(`coverage.py` 와 같은 원칙).
- 돌려줄 것
  - 사람: 이름, 부서, 직책, 재직 여부, 출처(wb, manual), 사번.
  - 자료 수: 담당(주, 공동), 작성. 이 사람 숫자일 뿐 다른 사람과 견주지 않는다.
  - 자동 특성(분포): 구역, 대상, 선종과 크기급(호선 PLM `ship_kind`, `ship_capacity`), 해석 유형(`model_summaries.sol`), 쓴 프로그램
    (`batches.origin.program`, WorkBench 에서 보낸 자료만), 권상 Wire 모델 여부.
  - 함께 일한 사람: 같은 자료의 공동 담당자(많이 함께한 순, 최대 8명). 이름을 누르면 그 사람 카드.
  - 남긴 지식: 결론을 쓴 자료 수, 주의점을 쓴 자료 수, 검토 서명한 자료 수(`reviewed_by`), 해결한 이슈 수(`entry_comments.resolved_by`).
    서명과 이슈는 사번이 있을 때만 센다.
  - 월별 목록: 호선 화면과 같은 월 기준(`hull_info._month` = 확정일, 없으면 등록일). 행마다 역할(주 담당, 공동 담당, 작성) 표시.

### 화면
- `pages/PersonPage.jsx`. 호선 화면(`HullPage.jsx`)의 구성을 따른다: 머리(이름, 부서, 직책, 퇴사 표시) → 왼쪽 월별 목록(탭: 담당한 자료, 작성한 자료),
  오른쪽 분포. 호선 화면의 `Distribution` 은 공용 부품으로 꺼내 둘이 같이 쓴다.
- 분포 행을 누르면 검색으로 간다(예: 이 사람 + 구역 선수부 = `?assignee=12&zone=선수부`).
- 월별 목록 머리에 '날짜는 LogBook 에 확정한 달입니다(해석한 시기와 다를 수 있음)' 한 줄. 3단계 전까지의 한계를 숨기지 않는다.

## 2단계 — 본인 편집

- 새 표 `person_profiles`(person_id PK, intro 200자, contact_topics 문의 받을 수 있는 분야, expertise JSON = 분류 목록(구역, 대상)의 대표 값,
  pinned JSON = 대표 자료 최대 3건, updated_by, updated_at). 명부(`people`)에 열을 더하지 않는 이유: 명부는 자료 담당자 지정용 공용 데이터이고,
  소개는 카드에만 쓰는 사람의 글이라 성격이 다르다.
- **전문 분야는 자유 입력이 아니라 분류 목록에서 고른다.** 자동 분포 옆에 '본인이 적은 분야'로 따로 보이고 섞지 않는다.
- 대표 자료는 보는 사람이 볼 수 없으면 숨긴다.
- 권한(추천, 구현 전 확인): 본인(로그인 사번 = 명부 사번) + LV3. 사번 없는 퇴사자 카드는 LV2 이상. 감사 `PROFILE_UPDATE`.
- 재구축: 사람이 쓴 글이라 `registry.json` 에 `profiles` 키로 남긴다(63 의견과 같은 방식, `ops/registry.py`). 자료 단위가 아니라 `entry.json` 에는 넣지 않는다.

## 3단계 — 연구 역사(설계 남음)

- 문제: 지금 날짜는 확정일과 등록일뿐이다. 예전 자료를 한꺼번에 올리면 역사가 그날 하루에 몰린다. `analysis_period` 열은 15 이후 쓰지 않고,
  파일 수정 시각은 `files` 표에 없다.
- 해석 시기 추정 순서(안): ① WorkBench 출처 `origin.created_at` ② 사람이 고친 값(`analysis_period` 를 다시 살림) ③ 호선 인도일(PLM)에서 거꾸로 추정
  ④ 확정일. 화면에는 추정인지 표시한다.
- 그 위에 연도 × 구역 격자(경력 지도)와 자동 이정표(첫 자료, 처음 다룬 선종과 구역, 첫 검토 서명).
- 결정할 것: `analysis_period` 를 다시 살릴지(입력 부담 vs 정확도), 웹 올리기 때 브라우저의 파일 수정 시각(`File.lastModified`)을 받아 둘지.

## 4단계 — 다른 화면과 잇기

- 비슷한 모델 찾기 결과의 담당자 이름 → 카드(선례를 찾다가 물어볼 사람까지 찾게).
- 자료 현황(갖춤 현황) 칸에 '이 칸을 해 본 사람'.
- 퇴사자 카드는 인수인계 묶음으로: 남긴 결론과 주의점을 한 화면에 모아 읽기.
