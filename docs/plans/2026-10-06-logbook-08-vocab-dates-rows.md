# 08 — 분류·날짜·검색 결과 행 개편 (P1)

선행: 03a·03b(검색·태그 동의어), 04b(썸네일). 사용자 승인(2026-10-06): SPDM/DMS 벤치마크
(SharePoint 관리 용어, M-Files 값 목록, Box enum, Windchill 결과 열) 결과 중 P1 3건.

목적: 같은 뜻의 값이 갈라져(FE 해석/FEM 해석, 강도평가/강도 평가) 필터 건수가 쪼개지는 문제를 막고,
결과 행에서 "언제 한 해석인가"와 "무엇이 들어 있나"를 한눈에 보이게 한다.

## 1. 해석 종류·구역 = 통제 어휘

**기존 태그 동의어 장치를 넓힌다(새 체계를 따로 만들지 않는다).**

- `tags` 표에 열 3개(`ADDED_COLUMNS` — 145 는 재시작으로 붙는다): `listed`(목록 용어, 기본 0) · `sort_order` · `active`(기본 1).
- 종류: `zone`(구역 — 기존 그대로 `entry_tags` 로 Entry 와 잇는다) · `atype`(해석 종류 — 새 종류. Entry 와는 잇지 않고
  `entries.analysis_type` 문자열이 대표 값을 갖는다. 태그 행은 용어·동의어 사전 역할만) · `free`(자유 태그 — 통제 안 함).
- 용어 = `listed=1` 인 대표 태그. 동의어 = `alias_of` 가 용어를 가리키는 태그(기존과 같은 한 단계 구조).
- **정규화 `canon(kind, 값)`**: 앞뒤·연속 공백 정리 → 같은 값(대소문자 무시)의 태그가 있으면 그 대표 값 →
  아니면 공백·대소문자를 뺀 열쇠로 용어·동의어와 비교(강도평가 = 강도 평가) → 그래도 없으면 원래 값.
- 기본 목록(그 종류의 용어가 하나도 없을 때만, API 시작 시 넣는다 — `VOCAB_SEED` 기록):
  - 해석 종류: 강도 평가, FE 해석, 진동 해석, 피로 평가, 좌굴 평가, 권상 해석, 계류 해석, 운송 해석, 기타
  - 구역: 선수부, 선미부, 화물창, 기관실, 거주구, 상갑판, 이중저, 기타
  - 기본 동의어 몇 개(FEM 해석·FEA → FE 해석, FWD → 선수부 등). 이미 다른 값에 묶인 태그는 건드리지 않는다.
- **입력**(정리 대기 카드·Entry 상세): 해석 종류 = 목록에서 하나 고르는 콤보박스, 구역 = 목록에서 고르는 칩.
  동의어를 치면 대표 용어로 바뀐다. 목록에 없으면 일반 사용자는 '기타', 관리자는 그 자리에서 용어 추가.
  서버도 막는다: 일반 사용자가 목록 밖 새 값을 보내면 `422 vocab_not_listed`(이미 그 Entry 에 있던 값은 통과).
- **관리 화면 `/admin/vocab` '분류 목록'**(관리자): 종류별 용어(사용 건수)·추가·이름 바꾸기(옛 이름은 동의어로 남음)·
  순서(위/아래)·사용 중지·동의어 추가/빼기, **목록 밖 값**(데이터에 있으나 목록에 없는 값과 건수) → '용어로 합치기'
  (Entry 값을 용어로 바꾸고 그 값을 동의어로 남김) 또는 '용어로 추가'. 모든 변경은 감사 로그(`VOCAB_*`),
  바뀐 Entry 는 Entry 마다 `ENTRY_UPDATE` 이력 + `entry.json` 다시 쓰기.
- 태그 화면은 자유 태그만 다룬다(구역은 분류 목록으로 옮김). 구역·해석 종류 동의어 묶기 API 는 관리자만.
- **CLI**: `vocab-report`(쓰지 않음 — 데이터의 서로 다른 값, 각 값이 어디로 바뀔지, 목록 밖 값) /
  `vocab-normalize [--apply]`(기본 목록 보장 + 동의어·표기 변형 값을 대표 용어로 바꿈). 다시 돌려도 바뀌는 것 없음,
  못 맞춘 값은 그대로 두고 '목록 밖 값'에 남는다. registry.json 에 용어 목록을 남겨 재구축 때 되살린다.
- **검색**: 해석 종류·구역 필터 건수는 대표 값으로 센다. 용어로 거르면 동의어·표기 변형 값도 걸린다.
  검색어가 동의어(예: FEM)면 그 용어의 Entry 도 맞는다.
- **태그**: 자유 입력 그대로. 검색 필터 `tag` + 필터 열 '태그' 추가. 태그 칩(상세·미리보기·결과 행·태그 화면)은 `/?tag=이름` 링크.

## 2. 날짜 = '해석 시기' 하나

- 결과 행: `해석 2025-11`. 없으면 흐린 '해석 시기 미입력'. 확정일로 대신하지 않는다.
- 필터 '연도' → **'해석 연도'**: 해석 시기의 연도만. 없으면 '시기 미상'(`year=unknown`).
- 확정일은 상세·미리보기에서만 `확정 2026-10-06`.
- 정렬 선택: 관련도 | 해석 시기 | 최근 등록(`sort=relevance|period|recent`). 주소에 없으면 검색어가 있을 때 관련도,
  없을 때 해석 시기(시기 없는 것은 뒤로). 서버가 적용한 정렬을 응답 `sort` 로 돌려준다.

## 3. 검색 결과 한 행

```
┌────────┬────────────────────────────────────────────────┬──────────────┐
│ BDF    │ 9002 선미 구조 국부 강도               ● 미확정 │ 해석 2026-01 │
│ 썸네일 │ 9002 · 선미부 · FE 해석 · 벌크선               │ E000005      │
│        │ BDF 2 · 보고서 1 · 도면 0 · 결과 0  #태그        │              │
│        │ 9002_선미응력.xlsx · 응력 … 최대 [응력] 210 …   │              │
└────────┴────────────────────────────────────────────────┴──────────────┘
```

- 왼쪽: 대표 BDF 썸네일 — 변환 완료 모델 중 노드(GRID)가 가장 많은 것(INCLUDE 전용 파일 제외). 없으면 종류 아이콘.
  서버가 `thumb: {file_id, model_key}` 를 준다.
- 둘째 줄: 통제 값만 고정 순서 — 호선 · 구역 · 해석 종류 · 선종. 호선 하나로 거른 검색이면 그 호선 칩은 뺀다.
- 셋째 줄: 종류별 파일 수(`kind_counts` — BDF·보고서·도면·결과는 0 이어도, 기타는 있을 때만) + 태그 링크.
- 발췌: 최대 2줄. 키보드 이동·클릭 미리보기·'비교에 담기'(파일 보기)는 그대로.
- 넓은 화면(1920)에서 행 내용 폭을 1080px 로 묶어 오른쪽 ID·날짜가 제목에서 멀어지지 않게 한다.
