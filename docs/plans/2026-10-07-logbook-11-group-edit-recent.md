# 11 — 검색 보기 기준(묶어 보기)·고치기 단계(변경하기 → 변경 완료)·최근 비교

선행: 10(즐겨찾기·사용자 설정), 09(결과 행·분류), 07(모델 비교). 사용자 요청(2026-10-07):
"검색 탭에서 구역별·호선별·올린 사람별을 상위 분류로 두고 그 기준으로 보게",
"세부 내용 변경은 변경하기 → 변경 완료를 눌러 끝내게(지금은 고치면 바로 반영)",
"모델 비교를 한 기록을 사용자별 '최근 비교'에 남겨 바로 다시 보게".

## 1. 보기 기준(묶어 보기)

- 검색 머리말 '보기' 선택: 묶지 않음(기본) | 호선별 | 구역별 | 해석 종류별 | 올린 사람별. 묶으면 '묶음' 순서(건수순·이름순)가 붙는다.
  **문서 보기에서만** — 파일 보기에서는 선택이 꺼진다(서버도 `unit=file` 이면 묶지 않는다).
- 주소 `group=zone`(+`gsort=name`)이 원본이라 그대로 공유된다. 고른 기준은 사용자 설정 `search.group`(10 의 `/api/me/prefs`
  화이트리스트에 추가, 값 = hull·zone·uploaded_by·analysis_type, null = 묶지 않음)과 localStorage 사본에 남아,
  주소에 `group` 이 없으면 그 기준으로 묶고 주소에도 적는다(검색은 한 번 — 검색 열쇠가 같다).
- API `GET /api/search?group=…` (`app/search/mysql_backend.py _groups`)
  - 맞은 Entry **전체**(쪽이 아니라)를 값으로 묶어 `groups: [{value, label, count, items}]` — items 는 묶음마다 처음
    `group_rows`(기본 5) 행. 행 모양은 검색 행과 같고(즐겨찾기 표시 포함) 한 번에 만든다.
  - 순서: 건수 많은 순(같으면 이름) 또는 `group_sort=name`. 값이 없는 Entry 는 맨 뒤 '없음' 묶음(`value=null`).
  - 값이 여럿인 Entry(호선 2개·구역 2개)는 **값마다 그 묶음에 들어간다** — `multi_valued` 건수를 주고 화면이 한 줄로 알린다.
  - 묶음이 많으면 `group_limit`(30)·`group_offset` 으로 나눠 받는다('묶음 더 보기').
  - 묶음 하나의 '더 보기' = 같은 질의 + `group_value=<값>`(없음 묶음은 `__none__`) + `limit/offset` → 그 값을 가진 행만, 같은 정렬.
  - 구역·해석 종류는 대표 값(08)으로 묶는다. 호선 머리에 선종, 올린 사람은 이름(label).
- 화면(`components/search/GroupedResults.jsx`): 묶음 머리(접기·값을 누르면 그 값으로 거르기·건수, 스크롤해도 위에 붙음) +
  기존 결과 행. 키보드 ↑/↓ 는 펼친 묶음의 행을 위에서 아래로 이어 옮기고(접은 묶음은 건너뜀) Enter·미리보기는 그대로.
  같은 Entry 가 두 묶음에 있어도 자리 열쇠(`_slot`)가 달라 따로 고른다. 요약 띠(09)는 그대로 위에.

## 2. 고치기 단계 — [변경하기] → [변경 완료]

- Entry 상세(`pages/EntryPage.jsx`)는 기본이 **읽기 화면**이다: 제목·설명은 글자, 속성은 찾기 링크(09)만. 칸별 '고치기' 단추와
  자동 저장(InlineText·칩 즉시 저장)은 없앴다.
- 머리의 **[변경하기]**(확정 자료만) → 제목·설명·호선·구역·해석 종류·해석 시기·태그가 입력칸이 된다(기존 ChipInput·VocabInput 을
  저장 없이 재사용). 위에 붙는 '고치는 중' 띠에 바뀐 칸 수와 이름, [취소]·**[변경 완료]**. 바뀐 칸은 라벨 옆 남색 점(+화면 읽기 '(변경됨)').
- **[변경 완료]** = 바뀐 칸 전부를 **한 번의 PATCH**(고치기 시작할 때의 version) → 이력(감사 로그 `ENTRY_UPDATE`)도 한 줄,
  `entry.json` 도 한 번. 성공하면 토스트 '변경을 저장했습니다.' 후 읽기 화면. 바뀐 칸이 없거나 값이 틀리면(제목 비움,
  해석 시기 YYYY-MM 아님, 호선 4자리 아님) 단추가 꺼진다. 순수 함수는 `lib/entryEdit.js`.
- **충돌(409 version_conflict)**: 고친 내용을 지키고 알린다 — [최신 내용 불러오기](최신 값 위에 내가 바꾼 칸만 다시 얹음 →
  확인 후 다시 완료) | [내 변경 버리기]. 고치는 동안 파일 추가 등으로 다시 불러왔는데 고칠 칸의 서버 값이 그대로면 새 version 으로
  조용히 갈아탄다(내 파일 추가로 충돌이 나지 않게).
- [취소]·Esc: 바뀐 것이 있으면 확인 대화상자. Ctrl+Enter = 완료.
- 저장하지 않은 변경이 있으면 떠날 때 묻는다(`lib/useUnsavedGuard.js`): 창 닫기·새로 고침은 beforeunload, 앱 안 이동은
  **데이터 라우터의 useBlocker**(링크·상단 검색·뒤로 가기 모두). 이를 위해 `main.jsx` 를 `createBrowserRouter`(모든 주소 → App)로
  바꿨다 — 화면 경로는 그대로 App 의 `<Routes>`. 데이터 라우터가 아닌 단독 렌더(테스트)에서는 앱 안 링크 누르기만 가로챈다.
- 백엔드 PATCH 는 이미 한 요청 = 감사 한 줄이었다(바꾸지 않음). 여러 칸 PATCH 가 한 줄로 남는 것을 테스트로 고정했다.

### 정리 대기 초안 카드 — 같은 원칙, 단계는 하나 줄임

- 이전: 칸을 벗어나면(제목·시기·설명)·칩을 고르면(호선·구역·해석 종류) **바로 PATCH**(자동 저장)였다 → 바꿨다.
- 카드는 원래 고치는 양식이라 [변경하기] 단계는 두지 않는다. 고치면 카드 안에 '저장하지 않은 변경 N칸 · 칸 이름' 줄과
  [되돌리기]·**[변경 저장]**(한 번의 PATCH)이 나온다.
- [확정]은 바뀐 칸이 있으면 **[저장하고 확정]** 으로 바뀌어 저장 → 확정 순으로 한 줄에 세운다(저장이 실패하면 확정하지 않고
  사유를 알린다). 나누기·합치기·옮기기도 먼저 저장한다. 기존 Entry 에 추가 제안(merge_into)은 그 한 칸만 바로 바꾼다.
- 폴링으로 새 Entry 객체가 와도 고친 칸은 남긴다(이전엔 글자 칸만 남겼다). 정리 대기 화면은 카드별 '고침' 상태를 모아
  떠날 때·탭을 바꿀 때 묻는다.

## 3. 최근 비교(사용자별, 서버)

- 표 `compare_history`(id, employee_id, file_ids JSON — 마지막에 연 칸 순서, ids_key = 정렬한 id, open_count, created_at,
  last_opened_at, UNIQUE(employee_id, ids_key)). 새 표라 시작 때 `create_all` 이 만든다. 개인 편의 정보라 registry·재구축 대상 아님.
- 남기기: 비교 화면(`/compare?ids=`)이 **2개 이상 모델**로 열려 0.8초 그대로 있으면 `POST /api/me/compares {file_ids}`.
  같은 묶음(순서 무관)은 한 줄 — 순서는 마지막에 연 순서, open_count+1. 사용자당 최근 20개. 모델(BDF) 파일만 세고 둘보다 적으면 422.
- `GET /api/me/compares` — 최근에 연 순서, 파일마다 이름·호선(대표)·Entry 번호·제목·상태·모델 상태·썸네일 key·`available`·`note`
  (`trashed`·`failed`·`pending`·`not_model`). 파일·Entry·호선은 질의 2번으로 묶어 읽는다. 영구 삭제된 파일은 읽을 때 빼고 행을 고치며
  (`dropped` 로 알림), 남은 모델이 둘보다 적으면 행을 지운다. `DELETE /api/me/compares/{id}`(내 것만, 404) · `DELETE /api/me/compares`(모두).
- 화면
  - 사이드 메뉴 '최근 비교'(찾기 묶음, 분류 다음 — 비교 화면에서도 활성) → `/compares` 카드 목록: 모델 썸네일 2~4개, 이름·호선·자료 번호,
    열 수 없는 모델 안내, '언제 · N번 열어 봄', [열기]·[삭제], 머리 [모두 지우기].
  - [열기]는 휴지통·모델 아님 파일을 빼고 남은 모델로 연다(변환 전·실패 모델은 칸 안에서 사유를 보인다).
  - 비교 바구니 띠의 **[최근]** 메뉴(최근 6개 + 모두 보기), 빈 비교 화면 아래 '최근 비교' 5개.
  - 코드: `lib/recentCompares.js`, `components/compare/RecentCompares.jsx`, `pages/RecentComparesPage.jsx`.
