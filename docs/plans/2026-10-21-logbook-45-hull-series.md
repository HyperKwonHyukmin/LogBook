# 45 — 시리즈 호선을 한 묶음으로

작성 2026-10-21 · 상태: **1~4단계 구현(개발 PC, 2026-10-21) — 145 확인(5단계) 남음** · 관련: 19(검색 호선)·26·44(갖춤 현황)·30(PLM 선박 정보)·35(관계 지도 기준)

## 왜(2026-10-21 사용자 요청)
같은 선종 · 같은 설계로 여러 척을 짓는 시리즈(예: 3척)는 호선 번호가 달라도 해석 자료로는 같은 배다.
3371 자료를 찾는데 3370 에 올린 모델이 안 나오거나, 갖춤 현황 · 관계 지도에서 세 척이 따로 갈라지면 쓸모가 줄어든다.

## PLM 근거 (30 계획서 '다음 후보 — 시리즈 호선', 145 실측 2026-10-21)
- `VT_PLM_SHIP` 에 `SHIP_PRE`(선행호선, VARCHAR2(4)) · `SHIP_SEQ`(시리즈 순번)가 있다 — 지금 쓰는 접속 · 뷰 그대로.
- 3370: `SHIP_PRE='3370'`, `SHIP_SEQ='1'` → 첫 호선은 선행호선이 자기 번호.
- **확인됨(series_check4)**: `SHIP_PRE='3370'` 인 행은 3370(순번 1) · 3371(순번 2) 두 척, 둘 다 `SHIP_TYPE_NAME='174K-LNG'` · `SHIP_TYPE_CODE='LG017'` · 같은 주기관.
  → **`SHIP_PRE` 를 시리즈 대표로 쓴다.** 시리즈가 아닌 배도 자기 번호를 가질 것으로 보여 혼자인 시리즈는 그냥 호선과 같다.

## 결정 (사용자, 2026-10-21)
- **자료에 단 호선 번호는 그대로 둔다.** 자료 카드 · 상세에는 실제 호선 번호가 보인다.
- **같은 시리즈 호선은 검색 · 관계 지도 · 갖춤 현황에서 같은 묶음으로 취급한다** — 켜고 끄는 선택이 아니라 기본 동작.
- 검색할 때도 마찬가지: 3371 로 찾거나 걸러도 3370 · 3372 자료가 나온다.

## 설계(추천안 — 구현 전에 확인)

### 시리즈 대표
- `hulls` 에 열을 더한다: `series_lead`(PLM `SHIP_PRE`, 없으면 NULL) · `series_seq` · `series_manual`(사람이 고쳤으면 PLM 이 덮지 않음 — 선종과 같은 방식).
- **묶음 키 = `series_lead or hull_no`.** 한 곳(`hull_info.series_key` 같은 함수)에서만 정하고 검색 · 관계 지도 · 갖춤 현황이 같이 쓴다.
- 묶음 이름: LogBook 에 있는 호선이 둘 이상이면 `3370 시리즈 (3370 · 3371 · 3372)`, 하나뿐이면 그냥 `3370`(지금과 같다).
- PLM 채우기(30)가 두 열을 더 읽는다. 이미 찾은 호선은 다시 조회하지 않으므로 **`app.cli plm-fill --series`(한 번)** 로 기존 호선의 시리즈만 채운다.
- 호선 화면: '같은 시리즈 3370 · 3371 · 3372' 줄 + 시리즈 대표 고치기(관리자).

### 검색
- 낱말 `3371`: 그 호선 자료(지금 점수) + **같은 시리즈 자료(조금 낮은 점수, 적중 이유 '같은 시리즈 3370')**.
- 호선 거르기 · 호선별 묶기: 값이 시리즈 단위(`3370 시리즈`). 거르기 건수도 시리즈 단위.
- 정렬 '호선순'은 실제 호선 번호 그대로.
- LogBook 에 없는 호선(예: 3372 자료가 아직 없음)을 쳤을 때 시리즈를 찾는 것은 이번 범위 밖 — `hulls` 에 있는 호선끼리만 묶인다.

### 관계 지도(35) · 갖춤 현황(26 · 44)
- '호선' 기준 = 시리즈 묶음. 행 · 무리 이름은 위 묶음 이름, 칸을 펼치면 자료마다 실제 호선 번호.
- 선종 · 크기급 기준은 그대로(이미 여러 호선을 묶는다).

### 그대로 두는 것
- 자료 저장(`entry_hulls`) · `entry.json` · WorkBench 보내기 · 감사 이력 — 실제 호선 번호.
- 선례 찾기(27) 점수 — 나중에 '같은 시리즈' 표시만 검토.

## 단계
1. 서버: `hulls` 열 3개(`ADDED_COLUMNS`), PLM 두 열 읽기 · `plm-fill --series`, `series_key` 함수, 호선 화면 API 에 같은 시리즈.
2. 갖춤 현황 · 관계 지도: 호선 기준을 `series_key` 로(응답에 묶음 이름).
3. 검색: 낱말 적중 · 거르기 · 묶기를 시리즈 단위로.
4. 프런트: 호선 화면 줄 · 대표 고치기, 묶음 이름 표시, 데모(`frontend/demo/mockApi.js`) 응답.
5. 145: Update → `plm-fill --series` → 시리즈 호선으로 검색 · 갖춤 현황 · 관계 지도 눈으로 확인.

## 1단계에서 바뀐 것 (2026-10-21)
- `plm_ship`: `SHIP_PRE` · `SHIP_SEQ` 를 더 읽어 `seriesLead`(번호 정규화) · `seriesSeq`. `series_keys(db, 호선들)` → {호선: 묶음 키},
  `series_members(db, 키들)` → {키: 같은 시리즈 호선(번호순)} — 2 · 3단계가 이것만 쓴다.
- `hulls.series_lead`(색인) · `series_seq` · `series_manual` (`ADDED_COLUMNS` · `ADDED_INDEXES`).
- `hull_info._apply`: 찾으면 시리즈를 PLM 값으로 — 단 `series_manual` 이면 일괄 채우기 · 자동 조회는 덮지 않고, 호선 화면 [선박 정보 검색]만 되돌린다(선종과 같은 규칙).
  감사 스냅숏에 시리즈 세 칸.
- 호선 API: `GET /api/hulls/{no}` 에 `series`({lead, seq, manual, members:[{hull_no, seq, entries}]}, 대표 없으면 null),
  `PATCH` 에 `series_lead`(LV2 이상, 빈 값 = 시리즈 아님, 형식 밖 422, 감사 HULL_UPDATE).
- CLI `plm-fill --series`: 이미 찾았지만 시리즈가 빈 호선(사람이 고친 것 빼고)도 다시 조회.
- registry `hulls[].series` · 재구축이 되살림.
- 테스트 `tests/test_hull_series_45.py`(6건), `test_plm_ship_30.py` 조회 모양에 두 키.

## 2~4단계에서 바뀐 것 (2026-10-21)
- 갖춤 현황 · 관계 지도 응답에 `hull_series`({호선: 묶음 키} — 자기 번호와 다른 것만) · `series_members`({키: 이 응답의 호선들} — 둘 이상만)
  (`plm_ship.series_view`). 프런트 `lib/hullSeries.js` 가 읽는다 — 값이 없으면(데모 · 옛 서버) 지금처럼 호선별.
  - 갖춤 현황: 호선 행 열쇠를 `h:<묶음 키>` 로, 시리즈 행은 호선 칩을 나란히(각각 호선 화면), 선종 · 크기급 행의 '호선 N척'은 실제 척 수 그대로.
  - 관계 지도: 호선 무리 = 시리즈('3370 시리즈'), 무리 설명에 '(3370 · 3371)', 찾기는 같은 시리즈 호선 번호로도, '호선 화면 열기'는 대표 호선.
- 검색: 행마다 `series`(묶음 키). 호선 거르기 · 건수 · 묶기 · 묶음 '더 보기'는 시리즈 단위(`hull=3371` → 적용 값 `3370`),
  이름은 `3370·3371 시리즈 · 174K LNG`(`hull_labels`). 낱말 `3371` 은 같은 시리즈 자료도 95점(`hull_series`, 정확 일치 100 아래).
  결과 행 · 호선순 정렬 · 분류 화면(browse) 호선 목록은 실제 호선 번호.
- 호선 화면: '시리즈' 줄 — 같은 시리즈 호선(순번 · 자료 수, 다른 호선은 링크), LV2 이상은 대표 호선을 고친다('직접 정함').
  [선박 정보 검색] 뒤에 시리즈 줄을 다시 읽는다. '이 호선 자료 검색'은 같은 시리즈 자료도 나온다(툴팁).
- 데모(`frontend/demo/mockApi.js`)는 시리즈 값을 싣지 않는다 — 데모 화면은 호선별 그대로.
- 테스트: `test_hull_series_45.py` 11건(응답 · 검색 낱말 · 거르기 · 묶기 · 분류 화면), 프런트 `coverage` · `graphModel` · `HullPage` 각 1건.
