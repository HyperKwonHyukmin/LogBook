# 24 — 정리 대기 초안에 보고서 첨부

## 사용자 흐름

1. BDF를 올리고 정리 대기의 초안 카드를 연다.
2. 카드의 파일 목록 아래 **파일 추가**를 누르고 보고서 파일 또는 폴더를 선택한다.
3. 추가 파일은 해당 초안으로 지정되어 기존 BDF와 같은 파일 목록에 붙는다.
4. 제목·소속·구역·해석 종류를 확인하고 **확정**을 한 번 누른다.
   BDF와 보고서가 같은 자료 번호와 보관 폴더로 이동한다.

보고서만 있는 초안에도 추가 파일을 첨부할 수 있다. PDF/DOCX/XLSX/PPT/PPTX 등
기존 업로드가 받는 형식을 사용한다. 확정 후 기존 보고서 목록·본문 색인 대상에 포함된다.
확정된 자료의 기존 파일 추가 동작은 유지한다.

## 처리 방식

- 기존 조각 업로드를 재사용하고 `target_entry_id`에 선택한 초안을 지정한다.
- 새 초안 첨부 요청은 `target_status=draft`를 함께 보내 다른 탭에서 이미 확정된 경우 거부한다.
- 워커는 업로드된 배치를 기존 방식으로 분류·해시 검사한 뒤 새 모듈
  `entries/draft_attachments.py`에서 해당 초안의 staging 폴더로 합친다.
- File ID는 유지하고 entry_id와 batch_id를 원래 초안에 맞춘다. 본문 추출·모델 변환 작업은 같은 ID를 계속 사용한다.
- 임시 제안 자료는 업로더·관리자만 볼 수 있다. 처리 중에는 별도의 승인 카드로 보여주지 않는다.
  추가가 끝나면 기존 초안의 공개 범위를 따른다.
- 초안의 제목·소속·구역·해석 종류·제목 생성 규칙을 변경하지 않는다. 파일 추가는 자료 버전만 갱신한다.
  화면에서 아직 저장하지 않은 제목·분류는 기존 DraftCard의 수정값 보존 동작을 사용한다.

## 동시 작업과 오류

- 업로드 시작부터 첨부 완료까지 확정·초안 버리기·나누기·합치기·파일 이동을 차단한다.
  서버도 행 잠금과 현재 배치 조회로 검사하므로 다른 탭의 요청도 차단된다.
- 같은 파일 이름은 기존 파일을 덮어쓰지 않고 `report (2).pdf`처럼 구분한다.
  BDF INCLUDE 참조의 이름 충돌 한계는 기존 파일 추가와 동일하다.
- staging 간 파일 이동 후 DB 기록 실패 시 이동을 되돌린다.
- 실패한 첨부는 원본을 보존하고 확정을 계속 차단한다. **첨부 연결 해제**를 선택하면
  파일을 삭제하지 않고 별도 배치로 남기며 원래 초안의 검토를 계속할 수 있다.
- 작업 이력 `DRAFT_FILES_ADDED`, `DRAFT_ATTACHMENT_RELEASED`를 기록한다.

## 검증

`backend/draft_attachment_tests`는 별도 SQLite를 사용하며 운영 DB와 `logbook_test`를 수정하지 않는다.
개발 PC는 로컬 PDF 쓰기에 DRM을 적용하므로 실제 파일 이동 검증은 사용자 확인된
공유 폴더의 `_poc/draft-attach-test-*` 임시 영역을 사용한다. 운영 Inbox/Vault와 분리하며
각 테스트가 만든 폴더만 경로 확인 후 제거한다. `LOGBOOK_ATTACH_TEST_ROOT`로 위치를 바꿀 수 있다.

검증 결과: 백엔드 분리 테스트 12개, 프론트엔드 관련 테스트 64개 통과.
공유 폴더의 임시 파일을 사용해 실제 업로드·첨부·공동 확정·이름 충돌·파일/DB 실패 되돌림을 확인했다.
별도 출력 경로의 프론트 빌드와 Python 문법 검사를 통과했다.
기존 MySQL 테스트 DB의 업로드 대상 계약 테스트는 초안 허용으로 갱신했으나,
병행 작업의 DB와 충돌하지 않도록 이번에는 분리 테스트로 검증했다.

```powershell
# backend
.\.venv\Scripts\python.exe -m pytest draft_attachment_tests -q
# frontend
npm test -- src/components/inbox/DraftAttachments.test.jsx src/components/inbox/DraftCard.test.jsx src/components/inbox/UploadZone.test.jsx src/pages/InboxPage.test.jsx src/lib/upload.test.js src/lib/labels.test.js
npm run build -- --outDir C:/Coding/WorkBench/.codex/draft-attachments-build
```

API/기존 워커가 소스를 다시 읽도록 재시작하고 프론트 빌드를 배포하면 적용된다.
병행 개발 중인 코드와 배포 파일을 보호하기 위해 테스트 빌드는 별도 경로를 사용한다.

## 개정 (2026-10-14) — 끌어 놓기로 첨부

초안 카드의 **[파일 추가] 칸에 탐색기 파일·폴더를 끌어 놓으면** 파일 선택과 같은 첨부 업로드가 된다.

- 칸에 `data-drop-zone` 표식(`UploadZone.DROP_ZONE_ATTR`). 정리 대기의 화면 덮개(`PageDropOverlay`)는 이제
  **놓기를 가로채지 않는다**(pointer-events 없음) — 놓기를 창 capture 단계에서 받되, 표식이 있는 칸 안이면 그 칸에 맡기고
  끄는 동안 덮개도 숨긴다. 칸 밖에 놓으면 예전처럼 새 배치.
- 탐색기 파일을 끄는 동안 [파일 추가] 칸이 덮개 위(z-50)로 드러나 '여기에 놓으면 이 초안에 첨부합니다'를 보인다.
  덮개 안내문에도 '초안에 붙이려면 카드의 파일 추가 칸에 놓으세요'가 붙는다(초안 카드가 있을 때).
- 첨부 진행 중·수정 불가면 올리지 않고 '첨부가 끝난 뒤 다시 놓아 주세요' 안내.
- 카드 전체(`DraftCard` article)의 끌기 처리는 **카드 사이 파일 옮기기(화면 안 끌기)만** 받는다 — 예전에는 탐색기 파일에도
  카드 테두리가 강조돼 받을 것처럼 보였다.
- 테스트: `DraftAttachments.test.jsx` 끌어 놓기 3건(대상 초안 지정 / 진행 중 거절 / 덮개가 칸 안 놓기를 가져가지 않음).

## 개정 2 (2026-10-14) — 디자인 검토(impeccable critique 27/40) 반영

- **놓을 곳 = 초안 카드 전체.** 탐색기 파일을 끄는 동안 수정 가능한 카드가 덮개 위(z-50)로 올라오고 머리에
  '<제목>에 첨부하려면 이 카드에 놓기'(위에 오면 '…에 놓으면 첨부합니다')를 보인다. `data-drop-zone` 은 카드(article)에 있고,
  업로드는 `DraftAttachments` 의 `ref.drop(dataTransfer)` 로 넘긴다. 올린 사람이 아니면 카드가 받지 않는다(빈 곳과 같이 새 배치).
- **덮개:** 받는 곳이 둘이면 가운데 큰 상자 대신 위쪽 안내 띠 하나('초안 카드에 놓으면 그 초안에 첨부, 빈 곳에 놓으면 새 배치').
  카드 위에서는 덮개를 숨기지 않고 문구만 바꾼다(깜빡임 제거). 초안이 없으면 예전 상자 그대로.
- '확인할 것' 줄을 '확정 전에 필요'(경고 아이콘) / '권장' 으로 나눔, 비활성 확정 단추에 `aria-describedby`.
- 첨부 완료·올리기 성공 문구의 초록 제거(초록은 확정·연결 전용), 정리 대기 문구의 줄표(—) 제거.
- [파일 추가]로 펼치면 포커스가 '파일 선택' 단추로 간다. 파일 행의 '옮기기…' 선택은 행 hover/focus 때만 보인다.
