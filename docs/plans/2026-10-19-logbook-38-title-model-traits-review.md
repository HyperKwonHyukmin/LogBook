## 1. 지금(20)
제목 초안 = `{호선} · {구역} · {해석 종류} · {구별자}` (예: `3496 · 선수부 · 강도 평가 · M04 rev3`)
- 구별자 = 원래 폴더/파일 이름에서 호선·구역·해석 종류 표기와 잡음(final·최종·copy)을 뺀 나머지.
- 사람이 안 고친 초안 제목만 값 따라 바뀌고, 관리자 '자료 정비'·`naming-cleanup` 으로 일괄 적용.

## 2. 약한 곳
1. **앞 세 칸이 같으면 제목이 같다** — 같은 호선·구역·해석 종류 자료가 여럿이면 구별자(파일 이름 찌꺼기)에만 기댄다. 구별자가 비거나 `M04`·`new model` 처럼 뜻이 없으면 목록에서 구별이 안 된다(그래서 20 이 '비슷한 제목' 경고를 둔다).
2. **모델이 어떤 모델인지 제목에 없다** — 빔 프레임인지 판·보강재 모델인지, 국부/전체, 규모(절점 수), 크기, 판(R0/R2)을 열어 봐야 안다.
3. 호선은 번호뿐 — 30 에서 PLM 선형(`174K LNG`)이 생겼는데 제목·목록에는 안 보인다.
4. 여러 값은 `3496 외 1` 로 줄여 무엇과 같이 묶였는지 안 보인다.

## 4. 방안
| | 방안 | 장점 | 단점 |
|---|---|---|---|
| **A (추천)** | **제목은 그대로 + '모델 특성 줄'을 자동으로 붙여 보인다**(저장 안 함). 상세 머리 제목 아래·검색 결과 행·관계 지도 툴팁에 `판+보강재 · 12.4k 절점 · 32×18×9 m · R2 최신 · 174K LNG` | 마이그레이션·재명명 없음, 재변환하면 저절로 맞음, 사람이 고친 제목을 덮지 않음 | 제목 문자열만 복사하면 특성이 안 따라감 |
| B | 제목 형식에 칸 하나 추가: `{호선} · {구역} · {해석 종류} · {모델 유형} · {구별자}` | 제목만 봐도 유형이 보이고 제목 검색에 걸림 | 재변환·파일 추가로 유형이 바뀌면 제목이 흔들림, 기존 자료 일괄 재명명(자료 정비) 필요, 제목이 길어짐 |
| C | 구별자를 **'대상 구조물' 통제 어휘**로(예: Mooring Fitting · Crane Pedestal · Lashing Bridge · Hatch Cover) — 08 의 구역·해석 종류와 같은 방식, 자동완성 + 목록 밖은 관리자만 | 파일 이름 찌꺼기 대신 뜻 있는 구별자, 같은 대상끼리 묶기·검색 가능 | 확정 때 고를 칸이 하나 늘어남, 초기 어휘 정리가 필요 |

**추천: A + C(선택 칸).**
- A 로 '어떤 모델인지'를 제목 밖에서 일관되게 보여 주고(규칙이 코드 한 곳이라 모든 화면이 같은 말),
- C 로 제목 네 번째 칸을 파일 이름 찌꺼기 → 통제된 '대상'으로 바꾼다. 대상이 있으면 `{호선} · {구역} · {해석 종류} · {대상} · {판 표기}`, 없으면 지금처럼 구별자. 필수로 만들지 않는다(BDF 필수 분류는 20 그대로).
- B 는 추천하지 않는다 — 제목이 변환 결과에 따라 바뀌면 '사람이 붙인 이름'의 안정성이 깨진다.
- 덤: `3496 외 1` → 호선 두 개까지는 `3496·3497`, 셋 이상만 `외 N`.

## 5. A 를 하면 할 일(구현 시)
- 백엔드: `entries/traits.py` — `model_traits(summary, revisions, hull)` 순수 함수(요소 구성 분류·규모 반올림·bbox 단위). 상세·검색 행·관계 지도 응답에 `traits` 한 줄(대표 BDF 기준 — 14 의 최신 판, 없으면 첫 변환 모델).
- 프런트: `ModelTraits` 한 줄 컴포넌트(아이콘 없는 회색 점 구분 글자, 상세 머리 제목 아래·결과 행 두 번째 줄).
- 확인할 것: bbox 단위(mm/m) 자료마다 다른지 — 145 실데이터 20건으로 먼저 본다. 기준이 없으면 크기는 빼고 시작.
- C 는 별도: `vocab` 에 kind `target` 추가, 정리 대기·상세 칸, `naming.compose_title` 의 네 번째 칸, 자료 정비 미리보기.
