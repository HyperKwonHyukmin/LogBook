# 68 — 과제 엑셀로 초안 만들기와 '올리기와 확정' 화면 재배치

작성 2026-11-23, 상태: **계획(구현 전)**, 관련: 20(필수 분류), 24(초안에 파일 첨부), 38과 40(대상), 46(담당자), 52(폴더째 올리기), 62, 66(올리기 절차)

## 배경
- 구조솔루션팀은 해마다 '통합과제' 엑셀(2026년 103행)로 과제를 관리한다. 열: NO., 과제 이름, 과제완료 여부, 과제의뢰서 NO., 담당자,
  아이템 분류(대상, Key point, 목적), Category, 평가 기준, 시작 날짜, 완료 날짜, 계획과 실 소요 M/H, 의뢰 부서, 의뢰자, 직책과장,
  유/무형 효과 설명과 금액, 기여도. 하단에 Category별, 의뢰 부서별 집계표(원형 그래프)가 있다.
- 과제 결과물(보고서, 해석 모델)은 LogBook 에 올라와야 하지만, 지금은 "올린 것만 보이는" 구조라 어떤 과제의 자료가 빠졌는지 알 수 없다.

## 결정(2026-11-23 대화)
- **별도의 '과제' 묶음이나 팀 관리 공간은 만들지 않는다.** 엑셀 한 행 = 초안 자료 1건(대부분의 과제가 자료 1건). 29 에서 '프로젝트' 칸이
  0건으로 끝난 것은 올리는 사람이 칸을 채워야 했기 때문이고, 이번에는 엑셀이 칸을 채운다.
- 엑셀을 넣은 사람의 '올리기와 확정'에 초안을 만들고, 사람이 그 초안에 파일을 넣고 확정한다. 담당자는 엑셀의 담당자 열로 따로 지정한다.
- **엑셀로 초안을 만드는 것은 LV2 이상**(사용자 결정).
- 흐름은 엑셀에서 LogBook 으로 한 방향이다. 확정된 뒤의 원본은 LogBook 이고, 엑셀은 입력 양식이다.
- 초안이 한꺼번에 수십 건 쌓이므로 **'올리기와 확정' 화면의 배치를 먼저 다시 짠다**(2부).
- 지금 구현하지 않고 이 계획을 확정한 뒤 구현한다.

## 1부 — 과제 엑셀 가져오기

### 1-1 틀과 알아보기
- **새 틀을 만들지 않고 팀 엑셀 양식을 그대로 받는다.** 담당자에게 따로 틀을 채우게 하면 팀 엑셀과 두 번 쓰게 된다.
- 알아보기: 시트에서 머리 행을 찾아 `이름`, `담당자`, `과제의뢰서 NO.` 세 열 이름이 모두 있으면 과제 엑셀로 본다(머리 서명).
  머리는 4~7행에 병합되어 있으므로 위아래 칸 이름을 이어 판정한다(예: '아이템 분류' 아래 '대상').
- 열은 **이름으로** 찾는다. 열 순서가 바뀌어도 된다. 필수 열(이름, 담당자, 과제의뢰서 NO.)이 없으면 어느 열이 없는지 알리고 멈춘다.
  아는 열이 아니면 무시하고 미리보기에 '읽지 않은 열'로 보인다.
- 하단 집계표, 다른 시트(평가 기준, Drop_Down)는 읽지 않는다. 행은 NO. 가 숫자이고 이름이 있는 줄까지만.

### 1-2 들어오는 길
| 길 | 처리 |
|---|---|
| 탐색기로 `999_LogBook\00_Inbox` 에 복사 | DRM 이 풀리는 기본 경로(설계 §1). 묶음에 **과제 엑셀 하나만** 있으면 '과제 묶음'으로, 다른 파일과 섞이면 지금처럼 일반 자료로 처리 |
| 웹 [과제 엑셀 올리기] 단추 | 평문일 때만. `HHIDRMC` 머리면 지금처럼 거부하고 탐색기 복사를 안내 |

- Inbox 는 낱개 파일을 **파일 소유 계정과 처음 본 시각의 간격**으로 묶는다(연달아 넣으면 2분을 넘겨도 한 묶음, 소유자를 못 찾은 파일끼리도 묶임,
  `ingest/inbox.py`). 그래서 과제 엑셀은 다른 파일과 시간을 두고 넣거나 폴더 하나에 엑셀만 넣도록 안내한다.
  소유 계정이 사번과 맞으면 바로 그 사람의 묶음이 되고, 맞지 않을 때만 '폴더에 직접 넣은 묶음'으로 간다.
- 암호문 그대로 들어온 엑셀(`Copy-Item` 등)은 과제 묶음 카드에 '암호화되어 읽지 못함, 탐색기로 다시 복사'라고 띄운다.

### 1-3 미리보기 뒤 초안 만들기
워커가 바로 초안을 만들지 않는다. 엑셀을 읽어 행 목록을 묶음에 저장하고, '과제 묶음' 카드가 미리보기를 보인다.
- 줄마다: 만들기 체크, NO., 과제 이름, 담당자(명부 대조 결과), 호선 후보, 상태, 알림(이미 있음, 명부에 없는 이름, 목록 밖 값).
- 기본 체크: 상태가 완료, 진행 중, 자체수행인 행. 미수행, 착수 전, 빈칸은 해제(체크하면 만든다).
- [초안 n건 만들기] 는 **LV2 이상인 올린 사람**만 누를 수 있다. 폴더에 직접 넣은 묶음은 '내가 올렸어요'로 가져간 사람이 LV2 이상일 때만.
  LV1 에게는 미리보기만 보이고 'LV2 이상만 초안을 만들 수 있습니다'.
- **과제 묶음은 새 상태를 쓴다.** 지금 워커는 `staged` 묶음만 처리하고 초안이 0건이면 바로 `done` 으로 닫으며, done 묶음은 목록에서 빠진다
  (`ingest/process.py` 131, 285행, `routers/batches.py` 107행). 과제 묶음은 읽기가 끝나면 `review`(미리보기 대기)로 두고 [초안 만들기] 뒤에 `processed` 로 넘긴다.
  - 만들기는 한 번만: 묶음 행을 잠그고 상태가 `review` 일 때만 진행(두 번 누름, 두 창 동시 요청 방지). 행 열쇠에 고유 제약(1-5).
  - 체크 0건이면 만들지 않고 [이 묶음 버리기]만 남긴다. 일부 행이 실패하면(열쇠 충돌 등) 나머지는 만들고 실패 행과 사유를 카드에 남긴다.
- **원본 엑셀과 가져오기 기록은 묶음의 staging 폴더에 남긴다**: `10_Vault\_staging\<묶음 키>\_task_sheet.xlsx` + `_task_import.json`(고른 행, 행 열쇠, 만든 초안 번호, 만든 사람).
  지금 entry.json 은 확정 자료에만 쓰이고(`entries/files.py` `write_entry_files`), 재구축은 파일이 있는 staging 폴더만 '폴더에 직접 넣은 묶음'으로
  다시 처리한다(`ops/rebuild.py` 365행). 파일 없는 과제 초안은 이 기록이 없으면 재구축 때 **사라진다**. 재구축은 `_task_import.json` 이 있는 폴더를
  과제 묶음으로 되살려 초안을 다시 만들고(만든 사람 = 기록의 사람), 그 폴더에 첨부된 다른 파일은 지금처럼 다시 처리한다.

### 1-4 행에서 초안으로
| 엑셀 열 | 초안의 어디로 | 비고 |
|---|---|---|
| 이름 | 제목 | 과제 이름 그대로. `title_source` 는 비워 둔다(이 열은 출처 종류가 아니라 '제목 초안을 만들 원래 이름'이다). 제목이 초안 형식과 다르므로 파일을 붙여도 자동 제목이 덮어쓰지 않는다(`quality.is_auto`) |
| 담당자 | 담당자(46) | 이름과 직책으로 명부 대조. 한 명만 맞으면 연결, 동명이인이나 없음이면 빈칸 + 알림 |
| 이름 속 호선 번호 | 호선(추정) | `ingest.hulls.extract_hull_candidates` 재사용, 아는 호선만. 2026년 엑셀 기준 103행 중 37행에 4자리 숫자 |
| 대상 | 대상 | 기존 대상 목록이나 동의어와 맞을 때만. 아니면 비우고 원문은 과제 정보에 남김 |
| 과제의뢰서 NO. | 과제 정보 `request_no` | 다시 넣기의 열쇠. 'X', 빈칸이면 열쇠 = `연도-#NO`(예 `2026-#18`) |
| Category | 과제 정보 `category` | 정해진 목록에서 고름(엑셀의 6종) |
| 의뢰 부서 | 과제 정보 `request_dept` | 글 + 자동완성(엑셀의 부서 목록 34개 + 이미 쓴 값) |
| 의뢰자 | 과제 정보 `requester` | 글(다른 부서 사람이라 명부와 대조하지 않음) |
| 목적, 평가 기준, Key point, 대상 원문 | 과제 정보 글 칸 | 검색 적중 대상 |
| 유/무형 효과 설명 | 과제 정보 `effect_note` | 글 |
| 시작 날짜, 완료 날짜 | 과제 정보 `started_on`, `finished_on` | 나중에 호선과 담당자 타임라인에 쓸 수 있다 |
| 금액, 기여도, M/H, 직책과장 | **넣지 않음** | 엑셀 계산식과 집계가 원본이고, 원가 금액이 사번만으로 로그인되는 LogBook 에 퍼진다 |

- 과제 정보는 엑셀 없이 올린 자료에도 쓸 수 있는 **선택 칸**이다. 초안 카드와 자료 상세 [변경하기]에 접힌 '과제 정보' 묶음으로 둔다.
- 저장: 1:1 표 `entry_tasks`(entry_id PK, `task_key` 고유, 가져온 묶음 키) — entries 를 더 넓히지 않고, 칸이 비면 행이 없다.
  entry.json `task` 키, 재구축이 읽는다. 감사 `ENTRY_TASK`. 스키마 변경 테스트는 `@pytest.mark.fresh_schema`.
- **Category 와 의뢰 부서는 분류 목록(`tags`)에 넣지 않는다.** 분류 목록 종류는 API 정규식, `KINDS`, 감사 필드 매핑에 고정돼 있고 값은 `entry_tags` 로
  연결되므로(`vocab.py`, `routers/vocab.py`) 넓히는 비용이 크다. Category 는 설정의 고정 목록(6종), 의뢰 부서는 `entry_tasks` 글 칸 + 자동완성으로 충분하다.
  동의어 묶기가 실제로 필요해지면 그때 옮긴다.
- **나누기, 합치기에서 과제 정보**(`entries/service.py` split, merge, 기존 자료로 확정 합치기):
  - 초안 나누기: 과제 정보는 원래 초안에 남고 새 초안에는 복사하지 않는다(행 열쇠는 하나뿐).
  - 초안끼리 합치기, 기존 자료로 합쳐 확정: 대상 자료에 과제 정보가 없으면 옮기고, 있으면 대상 것을 두고 감사에 버린 값을 남긴다. 원래 초안이 지워져도 열쇠가 고아로 남지 않게 같은 트랜잭션에서.

### 1-5 다시 넣기
- 같은 엑셀을 매달 다시 넣는 것을 기본으로 생각한다. 행 열쇠가 이미 초안이나 확정 자료(휴지통 포함)에 있으면 **만들지 않고** '이미 있음'으로 보인다.
  열쇠는 앞뒤 공백을 빼고 대문자로 맞춘 의뢰서 NO., 없으면 `연도-#NO`. 조회만으로는 동시 요청을 막지 못하므로 `entry_tasks.task_key` 고유 제약으로 막는다.
  영구 삭제된 자료의 열쇠는 풀린다.
- 엑셀 값이 LogBook 값과 다르면 미리보기에 바뀐 칸을 표시만 한다(1단계). 반영 기능은 실제로 필요해지면 따로.

### 1-6 파일 없는 초안
- 지금까지 초안은 항상 파일에서 생겼다. 과제 초안은 파일 0개로 시작하므로
  - 목록과 카드에 '파일 기다림' 상태를 둔다.
  - **파일이 0개인 초안은 확정을 막는다**(서버 422 `no_files` + 화면). 확인 결과 지금은 막지 않는다 — `confirm()` 은 파일 목록이 비어도 제목만 있으면 확정하고(`entries/service.py` 641행~),
    화면 검사(`inboxStatus.js` `draftChecks`)도 막지 않는다. 지금까지는 파일 없는 초안이 생길 길이 없었을 뿐이다.
  - 파일은 24 의 초안 첨부로 넣는다. 첨부는 '별도 첨부 묶음 → 임시 초안 → 원래 staging 으로 합치기'이고(`entries/draft_attachments.py`), 첨부 중이거나 실패한
    첨부 묶음이 남으면 확정과 버리기가 막힌다(`ensure_no_pending`). 합쳐진 뒤 분류, 해시 검사, 동일 BDF 막기는 지금과 같다.
- 과제 묶음은 모든 초안이 확정되거나 지워질 때 끝난다(지금 묶음 규칙과 같음). 진행 중 과제는 몇 달 남을 수 있다.

## 2부 — '올리기와 확정' 화면 재배치

### 문제
- 지금은 묶음마다 회색 틀 안에 초안 카드(편집 양식 전체, 파일 목록, 3D 미리보기)가 **모두 펼쳐져 세로로 쌓인다**(`BatchCard` → `DraftCard`).
  과제 엑셀 한 번에 수십 건, 폴더째 올리기(52) 몇 묶음이 겹치면 수십 화면을 내려야 하고 무엇이 지금 할 일인지 안 보인다.
- 서버 `GET /api/batches` 가 묶음 최대 200개와 그 초안, 파일 전부를 한 번에 보낸다. 오래 머무는 과제 초안이 늘면 매번 무거워진다.
- 사이드 메뉴 배지(62)가 '파일 기다림' 초안까지 세면 늘 큰 숫자가 떠서 의미를 잃는다. 배지는 초안 수와 처리 중 묶음을 함께 쓰고, 같은 요약 응답의
  `uploading`, `names` 는 '다른 창에서 올리는 중' 안내와 같은 이름 경고에도 쓰인다(`SideNav.jsx`, `routers/batches.py` summary).

### 배치: 목록 + 상세
- **목록(왼쪽)**: 한 줄 = 초안 1건. 상태 칩, 제목, 호선, 담당자, 파일 수, 묶음 이름, 올린 날. 묶음별 머리 줄(이름, n건, 접기, [이 묶음 모두 확정]).
- **상태**(서버가 계산해 준다):
  | 상태 | 뜻 | 확정 |
  |---|---|---|
  | 처리 중 | 워커가 분류, 변환 중 | 막힘(지금과 같음) |
  | 첨부 중 / 첨부 실패 | 24 첨부 묶음이 남아 있음 | 막힘(지금과 같음, `ensure_no_pending`) |
  | 파일 기다림 | 파일 0개 | **막힘(새 규칙)** |
  | 확인 필요 | 지금 [이 묶음 모두 확정]이 건너뛰는 이유가 있음(제목 없음, 동일 BDF, 권상 Wire 확인, 저장 안 한 변경) | 하나씩은 됨, 한꺼번에서는 빠짐(지금과 같음) |
  | 확정 가능 | 위에 해당 없음 | 됨 |
  - **'확인 필요'는 새로 막는 규칙이 아니다.** 호선 없음은 지금처럼 '보완 필요'로 확정되고, 구역과 대상은 선택이다. 상태 이름이 확정 규칙을 바꾸지 않게 한다.
- **위쪽 거르기**: 상태별 숫자 칩(눌러서 거르기), 묶음, 담당자(나 / 전체), 찾기(제목, 호선, 의뢰서 NO.).
  기본 정렬은 할 일 순(확정 가능 → 확인 필요 → 파일 기다림 → 처리 중), 같은 상태는 최근 순.
- **상세(오른쪽)**: 고른 초안 하나의 카드(지금 `DraftCard` 재사용, 같은 묶음 초안 목록 `siblings` 를 넘겨 파일 옮기기, 나누기, 합치기 유지). 3D 미리보기는 여기서만 연다.
- **저장 안 한 변경**: 고친 값은 `DraftCard` 안의 state 에만 있고, 카드가 사라지면 값과 표시(`dirtyIds`)가 함께 없어진다(`DraftCard.jsx` 79~97행).
  지금은 모든 카드가 늘 떠 있어 문제가 없었지만 상세 하나만 그리면 다른 줄 고르기, 거르기, 쪽 넘기기, 좁은 폭의 [목록으로]에서 값이 사라진다.
  그래서 상세를 떠날 때 저장 안 한 변경이 있으면 [저장하고 이동] [버리고 이동] [머무르기]를 묻는다(값을 위로 올려 보존하는 방식은 쓰지 않는다 — 카드 전체를 다시 짜야 함).
- 첨부 진행(24)은 상세가 닫혀 있어도 목록 줄의 '첨부 중' 상태와 폴링으로 따라간다.
- **좁은 폭**(기준은 구현 때 화면으로 정함): 목록만 보이고, 줄을 누르면 상세가 화면 전체로, [목록으로].
- **한꺼번에 하기**: 줄 체크 + [고른 것 확정]('확정 가능'만 체크됨). 확정은 지금처럼 하나씩 차례로 보낸다.
  MySQL 1213 교착(알려진 결함)은 이 화면과 따로 고칠 결함이다 — 한꺼번에 확정이 늘면 더 자주 만나므로 1단계 전에 따로 처리를 검토한다.
- **줄에 파일 끌어 놓기**: 과제 초안의 주된 일은 파일 넣기이므로, 목록 줄에 파일이나 폴더를 끌어 놓으면 그 초안에 첨부한다(24 재사용).
  화면 전체 끌어 놓기(새 묶음 올리기)와 겹치지 않게 줄 위에서는 줄이 이기고, 카드 사이 파일 옮기기 끌기와 구분한다(`DraftCard` 의 지금 구분 방식).
  첨부 중인 줄은 받지 않는다. 동일 BDF 로 빠진 파일의 사유, 409 안내, LV3 예외 경로는 지금과 같게 보인다.
- 탭(내가 올린 묶음, 보완할 자료, 폴더에 직접 넣은 묶음)과 위쪽의 올리기 단추, 가운데 진행 카드(52, 66)는 그대로 둔다.
- 사이드 메뉴 배지는 '확정 가능 + 확인 필요' 초안과 처리 중 묶음을 센다. 파일 기다림과 임시 첨부 초안은 세지 않는다. 결정 1 을 따르면 내가 담당한 초안도 센다(목록과 같은 기준).

### 서버
- `GET /api/inbox/drafts?scope=&state=&batch=&q=&offset=&limit=` — 가벼운 줄 목록과 상태별 숫자. 파일 목록은 넣지 않는다.
- 초안 하나의 상세(파일 포함)는 고를 때 따로 부른다.
- 묶음 쪽은 `GET /api/batches?lite=1`: 초안과 파일 없이 묶음 머리, 진행(queue, progress), 제외 파일, 자동 확정 결과, 첨부 대상만. 처리 전, 실패,
  동일 BDF 로 초안 없이 끝난 묶음, 자동 확정이 끝난 묶음처럼 초안이 없어도 보여야 하는 묶음은 이것으로 그린다. 지금의 전체 응답은 호환을 위해 남기되 화면은 쓰지 않는다.
- 상태 판정은 지금 화면의 `bulkConfirmPlan`, `draftChecks` 와 서버 `quality.missing_fields` 에 흩어져 있다. 서버 한 곳으로 모으고 화면은 그 값을 쓴다
  (규칙은 바꾸지 않고 자리만 옮긴다 — 같은 입력에 같은 결과가 나오는지 테스트로 대조).
