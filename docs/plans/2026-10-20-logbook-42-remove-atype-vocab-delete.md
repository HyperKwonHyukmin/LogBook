# 42 — 해석 종류 걷어 내기 · 구역/대상 삭제를 자료에 일괄 반영

작성 2026-10-20 · 상태: **구현 완료(개발 PC, 2026-10-20) — 145 화면 확인 남음** · 관련: 08(통제 어휘)·20(필수 분류·제목)·29(프로젝트 걷어 내기, 같은 방식)·38·40(구역·대상)

## 왜
- **해석 종류**(`entries.analysis_type`, 통제 어휘 `atype`)는 LogBook 에서 쓰지 않기로 했다(2026-10-20 사용자 결정).
  BDF 확정 필수 칸·제목 머리·검색 필터·묶기·분류 화면·갖춤 현황 거르기·선례 점수에 남아 있으면 판단 거리만 늘린다 → 29 처럼 한 번에 모두 뺀다.
- **구역·대상**은 분류 목록(관리)에서 이름을 바꾸면 이미 자료 전부에 반영된다(`vocab.update_term` → `_touch_tag_entries`).
  그런데 **지우기는 없고 '사용 중지'만** 있어 이미 붙은 자료에는 값이 남는다. 목록에서 지우면 그 값을 쓰는 자료에서도 한꺼번에 빠져야 한다.

## 그대로 두는 것
- **DB 스키마** — `entries.analysis_type` 열과 `tags.kind='atype'` 행은 남긴다(마이그레이션 없음). 어디서도 읽지 않는다.
- **옛 이력 표시** — 자료 이력 줄의 '해석 종류' 칸 이름, 활동 로그 라벨(옛 감사 기록을 읽을 수 있게).
- **이미 만들어진 제목** — 바꾸지 않는다. 사람이 안 고친 초안 제목은 다음에 값이 바뀔 때 새 형식이 되고,
  한꺼번에 맞추려면 145 에서 `naming-cleanup`(보고만) → 관리 '자료 정비'에서 골라 적용.

## 바뀌는 것 — 구역·대상 지우기
- `vocab.delete_term(db, storage, actor, term, ip)` — LV3. 용어와 그 동의어를 목록에서 지우고, 그 값(용어·동의어)을 단 자료에서 뺀다.
  - 확정 자료: 감사 `ENTRY_UPDATE`(before/after `zones`·`target`), version +1, entry.json 다시 쓰기.
  - 정리 대기·휴지통 자료: 값만 뺀다(이력은 확정 자료만 — 40 `move_term` 과 같은 규칙).
  - 목록 감사 `VOCAB_TERM_DELETE`(before: 값·동의어·자료 수), registry 다시 쓰기.
  - 값이 빠져 필수 분류(구역 또는 대상)가 비는 BDF 자료는 '보완 필요'가 된다 — 자료 정비 목록에 뜬다.
- API `DELETE /api/vocab/terms/{id}` → `{"value", "entries": [자료 번호…]}`. 화면은 지우기 전에 건수(목록의 사용 수)를 보여 주고 확인받는다.
- 이름 바꾸기는 지금처럼 자료 전부에 반영(옛 이름은 동의어로 남음). 화면 문구에 '쓰는 자료 N건에 함께 반영'을 밝힌다.

## 배포
마이그레이션 없음. `.env` 새 키 없음. 145 는 커밋·푸시 → Server Manager ⟳ Update(프런트 `dist` 포함).

## 테스트
- 백엔드: 해석 종류가 검색·자동완성·PATCH·응답·entry.json·필수 분류·제목에서 빠짐, 옛 `analysis_type` 이 남아 있어도 읽지 않음, `delete_term`(확정·대기·휴지통 자료, 동의어 값, 감사, entry.json).
- 프런트: 칸·필터·묶기·탭 없음, 분류 목록 [지우기] 확인 → DELETE.
