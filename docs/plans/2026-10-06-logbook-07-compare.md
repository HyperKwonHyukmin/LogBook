# 07 — 모델 화면분할 비교

선행: 04b·04c(뷰어), 06(해석 검증 배지). 사용자 결정(2026-10-06): 고르는 곳 = **모델마다 '비교에 담기' + 비교 바구니**,
최대 **4개**, 함께 보여 줄 것 = **카메라 동기화 · 특성 비교표 · 속성(PID·단면) 차이 · 표시 설정 공유**.

목적: 여러 BDF 모델(다른 호선, 같은 모델의 개정판 등)을 한 화면에 나란히 띄워 비교·분석한다.

## 1. 비교 바구니

- [비교에 담기] 버튼: 검색 결과의 모델 파일, Entry 파일 미리보기(모델), 전체 화면 뷰어(`/v/:id`) 머리줄.
  이미 담긴 모델은 [비교에서 빼기]. 변환이 끝나지 않은 모델도 담을 수 있다(비교 화면에서 상태 문구로 보인다).
- 바구니 = 화면 아래 고정 띠(담긴 것이 있을 때만). 칩(파일 이름 · 호선 · ×), [비교 열기], [비우기]. 최대 4개 — 다섯 번째는
  "최대 4개까지 비교할 수 있습니다" 알림.
- 저장: `localStorage`(이 브라우저 전용 편의 상태, try/catch — 없으면 메모리만). 다른 사람과 공유하지 않는다.
- 비교 화면 주소: `/compare?ids=12,34,56` — 주소가 원본이다. 주소로 열면 바구니도 그 목록으로 맞춘다. 주소를 보내면 같은 화면이 열린다.

## 2. 비교 화면 `/compare`

- 배치: 1개 = 한 칸, 2개 = 좌우, 3·4개 = 2×2(3개면 한 칸은 '모델 담기 안내'). 창 폭 < 1024px 이면 위아래로 쌓는다.
- 칸: 머리줄(파일 이름, 호선, Entry 링크, 해석 검증 배지, [크게 보기] ↔ [나란히 보기], [빼기]) + 3D 뷰포트 + 클릭 정보 카드(칸 안 오른쪽 아래).
  변환 대기·실패·DRM 등은 칸 안에 기존 `ModelNote` 문구.
- 공통 툴바(모든 칸에 적용): 색 기준(PID/그룹/단면/요소 종류), 선 / 3D 단면, 축 평면 자르기(X/Y/Z, 위치 — 각 모델 bbox 비율로),
  시점(평면·정면·측면·등각 = A/S/D, F = 화면 맞춤), 직교/원근, 카메라 동기화 켜기/끄기 + 기준.
- 카메라 동기화(기본 켬): 마지막으로 조작한 칸이 주인이고 나머지가 따라간다.
  - **각 모델 크기 기준**(기본): 방향(quaternion·up)과 '모델 크기 대비 거리·배율'을 맞춘다 — 각 모델 bbox 중심을 기준으로.
  - **같은 좌표**: 위치·target·zoom 을 그대로 복사한다(같은 좌표계 개정판 비교).
  - 직교 카메라는 `zoom` 도 맞춘다(Studio 교훈: position/quaternion 만 맞추면 배율이 어긋난다).
- 단축키는 마우스가 올라간 칸(없으면 전체)에 적용. `Esc` = 크게 보기 해제.

## 3. 비교 패널 (아래 접이식, 탭 2개, 높이 조절)

- **특성 비교표**: 행 = 요소 종류별 개수(CBAR·CBEAM·CROD·CQUAD4·CTRIA3·RBE2·RBE3·CONM2 등, 어느 모델에든 있는 것), 노드 수,
  크기(bbox X·Y·Z), SOL, PID 수, 독립 그룹 수, 변환 경고 수, 해석 검증 결과(배지 문구). 열 = 모델.
  **기준 모델**(기본 첫 번째, 열 머리에서 바꿈)과 다른 칸을 강조(숫자는 차이 +n/−n 도 표시).
- **속성 차이**: PID 합집합 × 모델. 칸 = 카드·단면 종류·치수(dims)·재료 번호(mid)(+ 있으면 근사 표시). 기본 '다른 것만', 토글 '모두 보기'.
  어떤 모델에만 있는 PID 는 '없음'. 행을 누르면 모든 칸에서 그 PID 요소를 강조(다시 누르면 해제).
- 데이터: `/api/files/{id}/model`(요약·solve) + `.lbm` 머리 JSON 의 `properties`. 재료 값(E·RHO)은 넣지 않는다(lbm 에 없으면 범위 밖).
  그룹 수는 프런트 `lib/modelGroups.js` 로 계산.

## 4. 성능

- 칸마다 뷰어 엔진 하나(WebGL 컨텍스트 ≤ 4). 화면이 바뀔 때만 다시 그린다(기존 엔진 규칙). 동기화는 requestAnimationFrame 한 번에 묶는다.
- 네 모델의 요소 수 합 > 2,000,000 이면 시작 표시는 '선'이고 "3D 단면은 느릴 수 있습니다" 안내.
- 칸을 빼면 엔진·geometry·texture 를 dispose 한다.

## 넣지 않음

한 화면에 겹쳐 그리기, 노드·요소 단위 자동 차이(같은 ID 좌표 차이), 비교 결과 저장·공유 DB, 재료 값 비교.

## 테스트

- 순수 함수: 바구니(추가·중복·최대 4·localStorage 실패), 주소 ↔ 목록, 배치 계산, 특성 비교표 행 만들기·차이, 속성 차이(합집합·다른 것만),
  카메라 동기화 변환(크기 기준 / 같은 좌표, 직교 zoom).
- 컴포넌트: 바구니 띠, 비교 화면(가짜 엔진 `test/fakeEngine.js`), 패널 탭·기준 모델 바꾸기·PID 강조 호출, 담기 버튼 3곳.
- 실측: 격리 스택(`logbook_test` + scratchpad 저장소 + 9096)에서 합성 모델 2~4개를 Playwright 로 열어 1366·1920 스크린샷.

## 구현 메모 (2026-10-06)

- **프런트만 고쳤다(백엔드 변경 없음).** 칸 머리줄·바구니 칩의 호선은 바구니에 담을 때 알던 값을 쓰고, 모르면(주소로 열기·뷰어에서 담기)
  칸이 `/api/entries/{entry_id}` 로 소속 자료의 대표 호선을 한 번 더 읽는다(`/files/{id}` 메타에는 호선이 없다).
- 순수 함수: `lib/compareBasket.js`(바구니·주소 ↔ 목록·저장) · `lib/compareLayout.js`(배치) · `lib/compareTable.js`(특성 비교표·속성 차이)
  · `lib/cameraSync.js`(동기화 변환). 화면: `components/compare/{CompareBasket,ComparePane,CompareToolbar,ComparePanel}.jsx`,
  `pages/ComparePage.jsx`(lazy 라우트 `/compare`).
- **엔진은 갈라내지 않았다.** 칸마다 기존 `useModelViewer` + `viewerEngine` 그대로이고, 엔진에 계약 4개만 더했다:
  `getCameraState()` · `setCameraState(state)` · `onCameraChange(cb)`(해제 함수 반환, `setCameraState` 가 옮기는 동안은 알리지 않는다)
  · `setPidHighlight(pids|null)`(찾은 PID 수 반환). `useModelViewer` 는 `engineRef` 를 내준다. 가짜 엔진(`test/fakeEngine.js`)도 같이 늘렸다.
- 카메라 동기화는 zoom 값을 복사하지 않고 **'보이는 짧은 쪽 반폭(view)'** 을 넘겨 받는 칸이 자기 화면 틀로 zoom 을 다시 센다
  (칸마다 화면 비율이 달라 zoom 복사는 배율이 어긋난다). 같은 좌표 방식은 엔진 좌표(각 bbox 중심 원점) ↔ 원래 좌표를 center 로 옮긴다.
  rAF 한 번에 묶는다. 시점·맞춤 단추·단축키는 마우스가 올라간 칸 → (동기화 중) 주인 칸 → (끔) 모든 칸 순으로 받는다.
- 바구니 띠는 **비교 화면(`/compare`)에서는 띄우지 않는다** — 화면 자체가 바구니라 패널과 겹친다. 띠가 떠 있으면 올리기 진행 상자(GlobalDrop)는
  `bottom-32` 로 올라가고, 검색 결과 끝에는 띠 높이만큼 여백을 둔다. 띠는 토스트(z-50)·올리기 상자(z-40) 아래(z-30).
- 칸 안 범례(ViewportLegend)는 넣지 않았다 — PID 색 규칙이 칸마다 같고, 칸 오른쪽 아래는 클릭 정보 카드 자리다.
  속성 행을 누르면 칸 왼쪽 위에 'PID n 강조 / 없음' 을 보인다(그 모델에 없는 PID).
- 비교 패널 높이·접힘은 이 브라우저 편의 상태(`lb.compare.panel.v1`), 처음 높이 = 창 높이의 28%(최대 240px). 기준 모델은 저장하지 않는다.
- 실측: 9096 격리 스택(logbook_test 추가 시드만, DB 초기화 없음) + 합성 4개(9999 개정판 둘 — PID 1 치수 변경·CBEAM·CROD·PROD 추가,
  9001 좌표가 먼 탑, 9002 떨어진 그룹 소형). 1366·1920 스크린샷 — 크기 기준·같은 좌표 동기화, 평면·3D 단면·그룹 색, Z 자르기, 표 2탭, PID 강조, 크게 보기.

### 알려진 한계

- 선택(클릭 정보)·절점·마커·PID 숨김은 칸마다 따로이고 공통 툴바에 없다(스펙 범위 밖).
- 동기화 '각 모델 크기 기준' 은 bbox 반지름 비율이라 모양이 아주 다른 모델(긴 배관 vs 정사각 갑판)은 화면을 채우는 정도가 다를 수 있다.
- 같은 좌표 방식에서 좌표계가 다른 모델은 화면 밖에 있을 수 있다(의도된 동작 — 주인 칸의 위치를 그대로 쓴다).
- 엔진의 새 계약(카메라 상태·PID 강조)은 jsdom 에 WebGL 이 없어 단위 시험이 없고, 변환 수식은 `cameraSync.test.js` 와 실측으로 확인했다.

## 후속 (2026-10-06) — 초기화·끝내기

- **[초기화]** (머리줄 오른쪽, [끝내기] 왼쪽 · 단축키 `R`. 공통 툴바 끝에 두면 1366 폭에서 툴바가 두 줄이 되어 칸이 34px 줄어 머리줄로 옮겼다) — 처음 비교를 연 장면으로 되돌린다. 공통 툴바 값(시점 등각·투영 직교·표시 선·색 PID·자르기 끔·
  카메라 동기화 켬 + 각 모델 크기 기준)·크게 보기·PID 강조를 기본값으로 두고, 화면이 다시 그려진 뒤(가려졌던 칸도 크기가 잡힌 뒤)
  칸마다 `useModelViewer().resetScene()` 을 부른다 — 선택·선택만 보기·찾기 끄기, 숨긴 PID·연결 그룹 다시 보이기, 경계선(요소 수 기준 기본값)·
  마커·절점 표시 기본값, 등각 시점으로 모델 전체 맞춤. 패널 탭·높이·기준 모델은 그대로 둔다.
  - 초기화 중 각 칸의 `setView('iso')` 가 일으키는 카메라 바뀜은 동기화로 넘기지 않는다(`quietRef`) — 넘기면 마지막 칸 카메라가 '크기 기준'으로
    나머지에 덮여 칸마다 자기 전체 맞춤이 아니게 된다. 남아 있던 rAF 도 취소하고 주인 칸을 비운다.
- **[끝내기]** (머리줄 오른쪽) — 비교를 열기 전 화면으로 돌아간다. 앱 안 이전 화면이 있으면 `navigate(-1)`(BrowserRouter 의 `history.state.idx > 0`,
  메모리 라우터는 `location.key`), 새 탭·주소로 바로 열었으면 검색(`/`). 바구니는 그대로 두어 다시 열 수 있다.
  칸 엔진은 언마운트 때 `useModelViewer` 정리 함수가 해제한다(시험: 끝내기 뒤 모든 가짜 엔진 `dispose`).
- 실측(9096 격리 스택, 1366×768): 회전·원근·그룹 색·Z 자르기·동기화 끔 → 초기화 화면이 처음 연 화면과 같음, 끝내기 = 들어온 뷰어(`/v/1`)로,
  주소로 바로 연 비교에서 끝내기 = `/`. 스크린샷은 세션 스크래치 `ux08/shots/08~11`.
- 시험: `ComparePage.test.jsx` 에 3건(초기화 — 상태·엔진 호출·동기화 안 옮김·`R` / 끝내기 — 이전 화면 + 바구니 유지 / 바로 연 경우 `/`).
