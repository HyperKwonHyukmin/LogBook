# 53 — 자료에 결론 한 줄 · 주의점 · 검토 서명 (2026-11-05)

상태: **구현**(백엔드 1280·프런트 800 통과). 52 는 같은 날 다른 세션의 '폴더째 올리기'라 53 으로 옮겼다. 51 2단계(지식화 1.5점 — 사람이 남기는 칸이 자유 입력 설명 하나뿐)의 첫 조각.

## 정한 것 (2026-11-05 사용자 결정)

- **판정 칸은 두지 않는다.** LogBook 의 해석은 구조 결과 판정이 아니라 모델이 해석되는지(유효성)만 보는 해석이다. 같은 이유로 51 의 'F06 결과 핵심값 카드' 제안도 뺀다.
- **결론 한 줄**(`conclusion`, 300자) — 이 자료로 무엇을 확인했고 무엇을 알게 됐는지. 검색 가산점은 제목(70) 다음 60, 검색 결과 행·미리보기·자료 머리에 보인다.
- **주의점**(`caveats`, 긴 글) — 다시 쓸 때 조심할 것(가정·단순화·알려진 한계). 검색 가산점은 설명과 같은 40.
- **검토 서명**(`reviewed_by`·`reviewed_at`) — 확정 자료만, **LV2 이상이고 작성자 본인은 못 한다**(검토 = 다른 사람의 눈). 결론이 비어 있으면 서명할 수 없다(서명할 내용이 없다). 취소는 서명한 사람·LV3.
- **서명 뒤 결론·주의점이 바뀌면 서명이 자동으로 풀린다**(서명은 그 내용에 대한 것). 풀림은 같은 변경 이력(ENTRY_UPDATE)의 '검토자' 칸으로 남는다. 파일 추가·분류 변경은 서명에 영향 없음.
- 판정과 이름이 겹치지 않게 '검증'이라는 말은 쓰지 않는다(기존 'Nastran 해석 검증'과 구별).

## 구현

| 층 | 무엇 |
|---|---|
| DB | `entries.conclusion VARCHAR(300)`·`caveats TEXT`·`reviewed_by VARCHAR(20)`·`reviewed_at DATETIME`(모두 NULL, `ADDED_COLUMNS`) |
| API | PATCH 에 `conclusion`·`caveats`(작성자·LV3), `POST/DELETE /api/entries/{id}/review`(감사 `ENTRY_REVIEW`·`ENTRY_REVIEW_CANCEL`), 응답 `conclusion`·`caveats`·`review{by,name,at}`·`can_review`·`can_unreview` |
| 재구축 | entry.json 에 `conclusion`·`caveats`·`reviewed_by`·`reviewed_at`(값 있을 때), `rebuild` 가 되살림 |
| 검색 | 결론 60·주의점 40 가산, 결과 항목에 `conclusion`·`reviewed` |
| 쪼개기·합치기 | 결론·주의점은 설명과 같이(받는 쪽이 비었을 때만), 서명은 옮기지 않음(초안은 서명 없음) |
| 화면 | 자료 머리에 결론(제목 아래)·주의점, 고치기 칸, 오른쪽 레일 '검토' 줄 + [검토 서명]/[서명 취소], 변경 이력 칸 이름, 정리 대기 카드 '결론' 칸(선택), 검색 결과 행·미리보기에 결론 한 줄과 '검토됨' |
