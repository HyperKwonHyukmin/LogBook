# 32 — 보고서 판 · 관계 지도 문서 관계

사용자 요청(2026-10-19): "관계지도에서 현재는 모델링 위주로만 관계가 형성되어 있는데 보고서 위주로도 지도 생성 가능한지 —
모델 없고 보고서만 있는 경우에도 생략되는 것이 아닌 지도가 구축되는 것. 모델 버전, 보고서 버전 이렇게."
검토안(같은 날) 2번을 그대로 구현한다. 1번(판 후보 찾기)·3번(본문 관계 추출)은 아래 '다음 차례'.

## 사용자 흐름

1. 관계 지도(`/graph`) 왼쪽 **자료 사이 관계**: 모두 | 모델 | 문서. 모델 선은 남색(형상만 같음·똑같은 BDF, 25 그대로),
   문서 선은 청록이다.
   - **사용한 모델**(실선) — 보고서에 '사용한 모델'(21)로 연결한 BDF 가 다른 자료에 있다.
   - **보고서 다른 판**(굵은 실선, 늘 보임) — 같은 보고서의 개정본이 다른 자료에 있다. "한 자료로 모아 판으로" 정리 신호.
   - **본문 비슷함**(점선) — 본문 의미가 가까운 보고서(추천 수준).
2. 모델 없이 보고서만 있는 자료는 **속이 빈 점**. 문서 선으로 다른 자료와 이어지고 기준 사이 굵은 곡선 건수에도 들어간다.
3. 선에 올리면 이어진 이유(파일 이름, 본문 겹침 %, 유사도). 기준 사이 곡선 설명에도 문서 관계 건수가 붙는다.
4. 자료를 고르면 오른쪽 상세에 파일 수(모델 n · 보고서 m), 같은 보고서의 다른 판이 있는 자료, 이 자료 보고서가 사용한 모델 /
   이 자료의 모델을 사용한 보고서, 본문이 비슷한 보고서가 있는 자료, 그리고 **모델 판**(R0→R1) 아래 **보고서 판**
   (Rev.A → Rev.B, 단계마다 '앞 판보다 쪽 2곳 바뀜 · 쪽 +1 · 본문 80% 같음').
5. 머리 안내: 본문 색인 전 보고서가 있으면 'N개는 본문 관계에서 빠졌습니다', 색인을 열 수 없으면 '사용한 모델과 파일 이름으로만'.

## 판단

- **점은 자료(Entry) 그대로, 판은 선이 아니다**(25 원칙). 파일 단위 점은 점 수가 몇 배가 되어 읽기 어렵다. 모델 판·보고서 판은
  자료 안 순서라 상세 열의 두 줄로 둔다. "R2 모델로 Rev.B 를 썼다"는 대응은 21 의 파일 단위 연결이 그대로 말해 준다.
- **보고서 판 = 모델 판(14)과 같은 이름 규칙** + 이름으로 짝이 없으면 **본문 겹침**(모델의 형상 서명·ID 자카드 자리).
  같은 종류 문서끼리만(PDF·DOCX ↔ PPT ↔ XLSX 를 섞지 않는다 — 같은 내용의 발표자료는 판이 아니다).
- **저장하지 않는다**(사용자 판 정리 없음, 자동 추정만). 자료 화면의 판 정리(14)처럼 보고서 판을 사람이 고치는 일은 다음 차례.
- 본문 겹침과 의미 유사도는 다른 것을 잰다. 겹침(글자 5개 조각의 MinHash 자카드)은 판(일부 고친 같은 보고서)에서 높고
  같은 분야의 다른 보고서에서 낮다. 의미 유사도(bge-m3 조각 벡터 평균의 코사인)는 주제가 가까우면 높다 → 판 판정에는 겹침,
  '비슷함' 추천에는 벡터.
- 본문 특징은 **'현재'인 색인만**(등록 SHA·경로·자료가 색인과 같음 — 22 `current_document`). 옛 본문으로 잇지 않는다.

## 처리 방식

- `app/report_index/features.py` — 보고서 한 건의 특징: MinHash(64개, 5글자 조각, 공백 제거) · 쪽(위치)별 본문 해시 ·
  평균 벡터(색인의 임베딩 모델 기준, 정규화). API 프로세스 안에 파일별 (sha256·indexed_at·벡터 수·모델) 열쇠로 들고 있다가
  바뀐 파일만 다시 계산(서버 재시작 뒤 첫 지도 요청은 모든 보고서 조각을 한 번 읽는다). `text_pairs`(띠 16×4 로 후보만),
  `similar_pairs`(1024행씩 행렬곱, 보고서마다 가까운 3개).
- `app/revisions/reports.py` — `entry_series`(14 의 `auto_groups`·`auto_labels` 재사용, 본문 겹침 ≥ 0.5 를 내용 규칙으로),
  `cross_pairs`(다른 자료 사이 같은 보고서의 다른 판).
- `app/graph.py` — 응답에 `entries[].models/reports/report_revisions`, `doc_pairs`, `doc_index`. 한 자료 쌍에 문서 관계 하나
  (우선 uses > rrev > text, `kinds` 에 종류별 수, uses 는 `from` = 보고서 쪽 자료).

| 관계 | 규칙 | 상한 |
|---|---|---|
| uses | `report_model_links` 의 보고서·모델이 서로 다른 보이는 확정 자료에 있다(휴지통 제외) | 쌍 6000 |
| rrev | ① 파일 이름 계열 열쇠(판 표시 뗀 이름)가 같고 본문 겹침 ≥ 0.3 — 색인이 없으면 줄기 6글자 이상 + 한쪽에 판 표시 ② 본문 겹침 ≥ 0.6 | 이름 묶음·띠 하나에 60파일 |
| text | 평균 벡터 코사인 ≥ `LOGBOOK_GRAPH_TEXT_SIM`(기본 0.85), 보고서마다 가까운 3개, 같은 임베딩 모델끼리 | |

- 권한: 25 그대로 — 보이는 확정 자료만 넘기므로 숨은 자료의 보고서와는 잇지 않는다(본문이 같아도).
- 색인을 열 수 없으면(`get_report_index` None) uses 와 이름 규칙만으로 그린다(`doc_index.available=false`).

## 본문 관계 지도(34 설계 초안) — 옵시디언식

옵시디언 지도의 뼈대는 **노트 = 점, 노트 안 [[링크]]·태그 = 선, 고른 노트 둘레만 보는 '로컬 지도', 거꾸로 링크(백링크) 목록**이다.
LogBook 에 옮기면 '노트'는 보고서, '[[링크]]'는 본문에서 뽑은 **개념 언급**이다. 사람이 링크를 달지 않아도 색인 본문(22)에서 만든다.

### 점과 선
| 점 | 원천 |
|---|---|
| 보고서(문서) | 확정 자료의 보고서(22 색인이 현재인 것) |
| 개념 | 호선(`hulls` 표)·구역·해석 종류(분류 목록)·구조물/부재(해치 코밍·크레인 기초…)·재질(AH36…)·하중 조건(Green sea·Lashing…)·규정(CSR·DNV…)·BDF 파일 이름 |
| 모델 | 본문에 이름이 나온 BDF(→ 21 '사용한 모델' 연결 제안) |

| 선 | 뜻 |
|---|---|
| 보고서 → 개념 | 본문에서 그 개념을 언급(근거 = 조각 위치 `page:12`, 발췌) — 옵시디언의 [[링크]] |
| 보고서 ↔ 보고서 | 함께 언급한 개념이 많음(드문 개념일수록 무겁게 — IDF) · 본문 비슷함(32) · 같은 보고서의 다른 판(32) |
| 개념 ↔ 개념 | 같은 보고서에 함께 나옴(동시 출현 수) |

### 뽑는 방법(두 단)
1. **사전·규칙(먼저, 확실)** — 호선 표·분류 목록·규정/재질/하중 낱말 사전, 정규식(`AH36`, `t=12`, `*.bdf`), 판정 문구(허용응력·OK/NG·안전율).
   조각 위치를 근거로 `mentions(file_id, chunk_id, kind, value, norm, source='rule')` 에 남긴다(22 색인 SQLite, 파생값 — 다시 만들 수 있음).
2. **LLM(선택, 야간)** — qwen2.5:7b 로 보고서마다 '핵심 개념 10개 + 그 근거 문장'. 근거 문장이 조각에 실제로 있는지 검사해 통과한 것만
   `source='llm'`. 새 개념은 bge-m3 로 기존 개념과 0.9 이상이면 같은 말로 묶고, 처음 보는 개념은 관리자 '개념 사전' 승인 대기에 둔다
   (분류 목록 Vocab 의 동의어 구조를 그대로 쓴다).
- 잡음 거르기: 보고서 2건 이상에 나오고 전체의 절반 이하에 나오는 개념만 지도에(너무 흔한 '검토'·'결과'는 선이 아니다).

### 화면 — '본문 지도'(관계 지도의 셋째 보기 또는 새 메뉴)
- **전체 지도**: 개념(사각·종류별 색)과 보고서(원) 힘 배치, 선 굵기 = 언급·동시 출현 수, 최소 연결 수 슬라이더, 확정 월 범위.
- **로컬 지도**: 보고서나 개념을 누르면 둘레 1~2단계만(옵시디언 로컬 그래프). 보고서 미리보기·자료 화면에서 바로 연다.
- **백링크 패널**: 개념을 고르면 '이 개념을 언급한 보고서 12건' + 위치 붙은 발췌(22 의 발췌 표시 재사용) — 원문 미리보기로 이동.
- **지도에서 묻기(GraphRAG)**: 질문 → 맞는 개념 → 그 둘레 보고서의 조각만 근거로 22 근거 요약(인용 [S1]…). 근거 범위를 지도로 보여 준다.
- (선택) **옵시디언 내보내기**: LV3 CLI `export-obsidian --out <폴더>` — 보고서·개념마다 .md(앞머리에 호선·구역·판, 본문에 [[개념]] 링크와 발췌)를
  써서 실제 옵시디언으로 연다. 본문 발췌가 밖으로 나가므로 권한·보안 검토 뒤에.
