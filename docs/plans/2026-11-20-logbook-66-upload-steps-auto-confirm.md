# 66 — 올리기 절차도와 '올리고 바로 확정'

작성 2026-11-20 · 상태: **구현** · 사용자 요청: "드래그앤드롭하면 '올리기와 확정'에 올라가고 확정을 눌러야 업로드된다. 처음 사용자에게 익숙하지 않다.
손쉬운 방법을 탐색하고, 지금 방식이 가장 효율적이면 절차도가 떠서 지금 2단계이고 확정을 눌러야 3단계가 된다는 것을 알 수 있어야 한다."

## 검토 결론

- 2단계(분류 확인)는 없애지 않는다. 확정을 막는 조건은 '제목 없음' 하나뿐이고(`lib/inboxStatus.js` `draftChecks`), 2단계는 자동으로 추정한
  호선, 제목, 구역과 대상을 사람이 한 번 보는 단계다. 같은 BDF 경고, 묶음 나누기와 합치기, 권상 Wire 요청도 이 자리에서만 한다.
  확정하면 바로 검색에 나오고 구조시스템연구실 전원(LV2)이 본다.
- A 절차도(모두에게) + B '올리고 바로 확정'(고르는 사람만, 기본 꺼짐)을 함께 넣었다(사용자 결정). C '분류를 먼저 받고 올리기'는 파일 한두 개도 창이 먼저 떠 오히려 번거로워 뺐다.

## A — 절차도 ① 올리기 → ② 분류 확인 → ③ 확정

- 부품 `components/inbox/UploadSteps.jsx`(끝난 단계 체크 아이콘, 지금 단계는 남색 채움과 굵은 글자, 읽기 글자 '(지금)', '(끝남)' — 색만으로 말하지 않는다).
  '바로 확정'이면 ② 를 '자동 확인'으로 쓴다.
- **가운데 진행 카드**(`UploadCenterCard`): 파일을 놓는 순간부터 절차도와 다음 할 일 한 줄. 올리기가 끝나면 묶음(`GET /api/batches/{key}`)을
  3초마다(최대 10분) 따라가 '서버가 정리하는 중' → '지금 2단계입니다. 올리기와 확정에서 초안 N건의 분류를 확인하고 [확정]을 누르면 3단계(검색에 나옴)'
  와 [올리기와 확정으로 가기](그 화면이면 '아래 묶음에서 확인'). 바로 확정이면 '확정까지 끝났습니다. 자료 N건이 검색에 나옵니다' 또는 남은 초안 수.
  기존 자료에 파일 추가에는 확정 단계가 없어 보이지 않는다(`u.attaching`).
- **올리기와 확정 묶음 카드**(`BatchCard` `BatchSteps`): 정리 중 / 2단계(초안 확인) / 3단계 끝(바로 확정한 자료 링크, 건너뛴 초안의 이유).
- 토스트 문구는 '올렸습니다. 다음 단계는 올리기와 확정에서 이어집니다.'로(바로 확정일 수도 있어 단계는 카드가 말한다).

## B — '올리고 바로 확정'

- 폴더 올리기 창 아래 체크 칸(기본 꺼짐, 마지막 선택을 이 브라우저에 기억 `logbook.upload.autoConfirm`). 켜면 단추가 [올리고 확정]. 파일 추가 창에는 없다.
- `POST /api/uploads` `auto_confirm: true` → 묶음 `preset.auto_confirm`(표 변경 없음). 정리(`ingest/process.py` `process_batch`)가 끝나면
  `ingest/auto_confirm.py` 가 초안마다 올린 사람 이름으로 확정한다(감사 ENTRY_CONFIRM 도 올린 사람). 하나가 실패해도 나머지는 간다.
- 건너뛰는 초안(올리기와 확정에 남음): 제목 없음, 똑같은 BDF 가 이미 있음, 권상 Wire 모델 확인, 같은 파일이 이미 있음(두 번 올린 것일 수 있다),
  기존 자료에 추가하라는 제안. 앞의 셋은 '이 묶음 모두 확정'(52)과 같은 규칙이고 뒤의 둘은 더 조심스럽게 더했다. 호선 없음은 막지 않는다(43, '보완 필요').
- 결과 `preset.auto_result = {confirmed: [E…], kept: [{entry_id, reason}]}` — 묶음 응답 `auto_confirm`, `auto_result`. 모두 확정해 `done` 이 된 묶음도
  하루(`AUTO_DONE_HOURS`) 동안 '올리기와 확정' 목록에 남겨 3단계 완료와 링크를 보인다.
