## 1. 화면 — '변경 보기'

한 화면(한 뷰포트)에 **뒤 판(b)** 을 그리고 바뀐 것만 색으로 띄운다.

| 범주 | 그리는 모델 | 색(토큰) | 모양(색약 보조) |
|---|---|---|---|
| 추가(요소·강체·절점) | b | `diff-add` 청록빛 초록 #35C9A0 | 실선·채운 면 / 절점 = 채운 원 |
| 변경(연결·PID·카드·방향/오프셋·강체 독립/종속/그 밖) | b | `diff-chg` 주황 #F5A524 | 실선·채운 면 |
| 이동한 절점 | b | `diff-chg` | 채운 원 + 선택하면 이동 전 위치(옅은 고리)와 점선 화살표 |
| 구속이 바뀐 절점(`loads.spc_nodes`) | b(없으면 a) | `diff-chg` | **네모** 점 |
| 삭제(요소·강체·절점) | **a** — b 좌표계로 옮겨 겹친다 | `diff-del` 붉은 분홍 #F0607A | **반투명 면 + 점선** 테두리 / 절점 = 빈 고리 |
| 변경 없음 | b | `diff-same` #5B6178 | 반투명 회색(흐리게), '바뀐 것만 보기'면 숨김 |

- 색은 Okabe–Ito 계열(파랑 쪽 초록·주황·붉은 분홍)을 어두운 뷰어 바탕(#1A1A2E)에 맞춰 밝혔다. 초록/주황/빨강을 구별 못 해도
  **모양**(채운 면·선 / 반투명+점선 / 원·고리·네모)과 **범례 글자**로 갈린다(PRODUCT '상태는 색만으로 말하지 않는다').
- 색은 `lib/pidPalette.js` `DIFF_COLORS`(엔진)와 `index.css` `--color-diff-*`(범례 색 칸) 두 곳에 같은 값 — DESIGN 15번(토큰 밖 hex 금지)에 따라 토큰을 먼저 더했다.
  변경 보기 동안 PID 색·RBE/질량/SPC 마커 색은 끈다(마커 마젠타·SPC 초록이 diff 색과 겹친다). 끄면 원래대로.
- **범례**(뷰포트 왼쪽 위): 범주마다 색 칸(모양) · 이름 · 개수 · 켜기/끄기 체크. 잘린 목록은 `연결 변경 12,000개 중 5,000개만 표시`.
  3D 로 그릴 수 없는 ID(솔리드·스프링 등 lbm 밖 요소, 모델에 없는 ID)는 `3D 에 없는 N개` 로 따로 적는다.
  아래에 **[바뀐 것만 보기]**(변경 없는 부분 숨김)와 **[바뀐 곳으로 맞춤]**.
- **클릭** → 뷰포트 오른쪽 아래 **전후 값 카드**: 범주 배지(색+글자) · 종류·ID · 카드 앞→뒤 · PID 앞→뒤 · 절점 연결 앞→뒤 · 좌표 앞→뒤(이동 거리) ·
  강체 기준/연결 절점 앞→뒤 · 방향 벡터·오프셋 앞→뒤. 값은 아래 §3 API 로 읽는다. 이동 절점·연결이 바뀐 요소를 고르면 **이동 전 모양을 옅게**(점선) 겹친다.
  변경 보기에서는 **바뀐 것을 먼저 고른다**(변경 피킹 장면을 먼저 보고 없을 때만 일반 피킹) — 회색 반투명 뒤의 주황이 눌린다.

### 진입점
1. 변경 요약 패널(`RevisionDiffPanel`) 머리 — **[3D로 변경 보기]** (기존 [두 판 3D 나란히 보기] 옆).
2. 판 흐름 줄 칩 옆 작은 단추(입체 아이콘, `R0 → R1 3D 변경 보기`) — 비교가 끝난(`done`, 같지 않음) 칩에만.
3. 나란히 비교(`/compare`)에서 모델이 2개이고 **같은 자료의 같은 계열**이면 머리줄에 **[나란히 | 변경 보기]** 토글.
   계열 순서로 앞/뒤 판을 정한다(주소 `ids` 순서를 그 순서로 바꾼다).

주소: `/compare?ids=<a>,<b>&view=diff` — 07 비교 화면 안의 보기 하나. 주소가 원본이라 그대로 보내면 같은 화면이 열린다.
계열이 아닌 두 파일(14 '두 판 고르기')도 패널에서 들어오면 열린다(토글은 계열일 때만 보인다). 칸이 2개가 아니면 나란히로 돌아간다.

### 비교 화면 안에서
- 공통 툴바: 표시(선/3D 단면)·투영·자르기·시점·맞춤은 그대로 쓴다. **색 기준은 잠근다**('변경' 고정, 단추 비활성 + 이유 툴팁). 카메라 동기화는 칸이 하나라 숨긴다.
- 비교 패널(특성표·속성 차이)은 그대로 — 속성 행 PID 강조도 그대로 덮어 그린다.
- 초기화(R): 범주 켜기·'바뀐 것만'·선택을 처음으로. 끝내기: 이전 화면.
- 비교가 아직이면(요청 없음·대기·계산 중) 칸 안에 상태 문구 + 진행. 요청은 화면이 연다(POST — 이미 있으면 그대로). 실패면 이유.

## 2. 렌더 — 기존 경로 재사용, 요소별 객체 없음

엔진 계약에 둘을 더한다: `setDiff(spec | null)` · `setDiffLayers(layers)` · `setDiffFocus(focus | null)`.

- **변경 없음 = 기존 PID 묶음 그대로**, 재질만 회색·반투명(`depthWrite` 끔)으로 바꾼다(되돌리면 원래 색·불투명). 3D 단면의 InstancedMesh 도 같은 처리.
  깊이를 쓰지 않으므로 회색 뒤의 바뀐 것이 가려지지 않는다.
- **추가·변경 = 기존 공유 위치 버퍼(`positionAttr`) + 그 범주 요소만 고른 인덱스 버퍼**(쉘 삼각형·경계선·1D 선분). 범주마다 Mesh/LineSegments 몇 개뿐이다.
  인덱스는 순수 함수 `lib/revisionDiff3d.js` `diffIndexBuffers(geometry, elemClass)` 가 PID 묶음의 `shell/shellElem`·`beams/beamElem` 에서 걸러 만든다(O(요소 수), TypedArray).
  1D 는 화면 고정 굵기 선(3px, `LineSegments2` 하나), 쉘은 불투명 면 + 테두리. 그룹 숨김 셰이더 고리(lbGroup)를 그대로 단다.
- **3D 단면**: 바뀐 1D 는 단면 묶음마다 `InstancedMesh` 하나(같은 단면 기하 공유, 행렬은 단면 행렬에서 복사, `instanceColor` 로 범주 색).
- **삭제(고스트) = a 모델**: 프런트가 a 의 lbm 을 함께 받아(`parseLbm` 은 복사 없는 보기) 삭제 요소·강체·절점만 **쓰인 절점만 모은 작은 위치 버퍼**로 만든다
  (`ghostGeometry`, b 의 bbox 중심 기준 좌표). 면 = 반투명 빨강, 테두리·1D = 점선(`LineDashedMaterial`). 상한 5000 이라 작다.
- 절점(추가·이동·삭제·구속) = 범주마다 `Points` 하나(원/고리/네모는 점 텍스처로), 화면 고정 크기, 깊이 검사 끔(맨 위).
- 피킹: 변경 피킹 장면(바뀐 요소·강체·고스트, 인덱스를 풀어 순번 색)을 **먼저**, 없으면 기존 피킹(바뀐 것만 보기면 기존 피킹은 쓰지 않는다).
  절점은 CPU 화면 거리(바뀐 절점 목록만, ≤ 2만).
- 자르기(renderer.clippingPlanes)·그룹 숨김·카메라·투영은 기존 그대로 따라온다. `setModel`/`clearModel` 이 diff 를 지운다.

## 3. API — 전후 값

`GET /api/files/{a}/diff/{b}/item?kind=element|node|rigid&id=<ID>`
- 두 판의 **lbm**(변환 결과, `20_Derived`)에서 그 ID 를 찾아 앞·뒤 값을 준다. 원본 BDF 는 다시 읽지 않는다(빠르고 DRM 무관).
  최근 lbm 4개를 메모리에 둔다(같은 쌍을 연달아 누를 때 다시 풀지 않게).
- 응답: `{kind, id, status: added|removed|changed|same|missing, changes: [...], a: {...}|null, b: {...}|null, detail: {...}}`
  - 요소: `card`·`pid`·`nodes`(절점 ID)·`coords`(각 절점 좌표)·1D 는 `orient`·`offsets`(v2). 질량(CONM2…)은 `mass`.
  - 절점: `xyz`, 그리고 `move`(거리).
  - 강체: `card`·`center`(기준 절점)·`others`(연결 절점).
  - `changes` = 두 lbm 값에서 바로 보이는 차이(`card`·`pid`·`nodes`·`xyz`·`orient`·`offsets`·`center`·`others`·`mass`).
  - `detail` = 14 상세에 그 ID 가 든 목록 이름(예: `elements.pid`, `rigids.dep` — 종속 추가/삭제 ID 포함). 비교가 아직이면 빈 값.
    lbm 에 없는 칸(직접 입력 값 등)만 바뀐 경우를 상세가 알려 준다(`elements.other`).
- 권한: 두 파일 모두 볼 수 있어야 한다. 하나라도 볼 수 없으면 **404**(13·15 — 존재를 숨긴다). 같은 파일·모델 아님 422,
  두 모델 변환 결과(lbm)가 없으면 409 `model_not_ready`, `kind` 오류 422. 보기 동작이라 LV1 도 된다.

### 성능
- 색칠 준비(분류 + 인덱스 버퍼 + 강체 + 고스트 + 범례) — node 순수 함수 측정(스크래치 `diff16/perf16.mjs`), 합성 **40만 요소**(쉘 36만·1D 4만), 범주마다 ID 5000:
  **43~72ms**(4회). 요소별 객체 없음 — 범주마다 Mesh/LineSegments/Points 몇 개, 위치 버퍼는 공유(인덱스만 새로).
- 실화면(swiftshader 소프트웨어 GL, 1920×1080): 합성 **30만 쉘 쌍**(30.3만 → 30.3만 요소, PID 변경 11,000 → 5,000 표시) 변경 보기 열기 0.8~1.8s(두 lbm 받기·파싱 포함),
  색칠 준비 29~40ms, 마우스 끌기 20번 0.55s, JS 힙 72MB. 같은 쌍의 서버 변환 12~14s·비교 9~10s(14 작업 그대로).
- 전후 값 API: 두 lbm 을 한 번 풀면 메모리(최근 4개)에서 찾는다(numpy 열 검색).

### 사용자가 할 일
- API 재시작(새 API 한 개). DB·워커 변경 없음 — 14 의 비교 결과(.rdiff)를 그대로 쓴다. 프런트는 `frontend/dist` 갱신본.

### 남은 한계
- ID 목록이 5000 에서 잘리면 3D 에도 앞 5000개(ID 순)만 칠한다(범례에 '…개 중 5,000개만 표시'). 넘는 것은 회색이다.
- 3D 로 그릴 수 있는 것은 lbm 이 아는 1D·쉘·RBE2/RBE3·절점뿐 — 솔리드·스프링·그 밖 강체(RBAR 등)는 '3D 에 없는 N개'로만 센다. 질량(CONM2) 변경은 칠하지 않는다(전후 값 API 는 준다).
- 재번호 모델은 14 처럼 '전부 삭제 + 전부 추가'로 보인다. 절점만 움직인 요소는 '변경'으로 칠하지 않는다(절점은 이동 범주, 카드에는 좌표 변화가 보인다).
- 고스트(삭제)는 연결 그룹 숨김을 따르지 않고, 바뀐 1D 굵은 선은 그룹 숨김을 따르지 않는다(비교 화면에는 그룹 숨김이 없다).
- 볼 수 없는 파일로 연 비교를 '최근 비교'에 남기려다 서버가 422 를 주는 것은 11 부터의 동작(화면은 조용히 넘긴다)이다.
